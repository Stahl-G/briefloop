# 语义判断实验政策

本目录仅产生研究观察与待复核提示。任何类别、概率、阈值命中或人工实验标签，都不能直接改变正式交付、Evaluator 范围、来源事实状态或 Wiki 学习许可。低优先级和未知项仍保留，确定问题及核心冲突仍须复核。

## 数据与标签

- 冻结明确的报告版本、来源内容及检查对象；以内容哈希标识数据集和各对象。按同一报告和共享来源分组拆分，避免同组泄漏到多个 split。
- 自然材料与合成材料分组报告，不混算质量。合成数字案例的构造标签只刻画模板场景，不能证明自然分布效果。
- `change_materiality`、`conclusion_update` 必须由人工按任务目标标注，不能把模型意见或合成偏好记为人工真值。没有标签、标签冲突及 unknown 单列，不按正确或错误凑样本。
- 盲标页面不显示模型判断；复核页面另存处置。标签中记录的 reviewer 是自报身份，不是认证后的人员证明。人工标注需要独立的实际流程，CLI 不替人完成此事。

## 概率与对照

保留三条路径：保守规则、仅 choice 的低成本 LLM、要求完整类别概率的 LLM；Jev 本身返回类别和概率。概率变体校验类别全集、数值范围、总和及所选类别是否为最大概率；离散对照不伪造概率。阈值按正类概率之和拟合，只改变实验中的二分类统计，不构成产品放行规则。

概率是模型输出的声明，不能当成真实性或置信保证。验收除误报 FP、漏报 FN、precision/recall 外，报告正类 Brier、固定十等宽箱 ECE 和概率直方图。分布总和允许的舍入偏差经原校验器接受后，在统计时统一归一到 1。离散预测和代码前置过滤不进入概率指标；代码过滤数量单列。小样本 ECE 很不稳定，不能单独证明校准有效。

## 阈值和一次留出

1. 开发集 `dev` 可探索。完成所有预定对照臂的 dev 后，再逐臂 `freeze-policy`。有概率的每个任务/材料类型必须同时有正负开发标签；缺少标签的任务不能冻结。
2. 冻结策略绑定：数据集身份和分组、dev 运行/结果/标签哈希、问法、代码、供应商、请求模型、API 返回模型身份、端点、概率变体、前置过滤、执行边界与阈值。固定目标为开发集二分类 balanced accuracy 最大，平分取更高阈值；此目标不能在留出结果出来后更换。
3. 概率臂与离散臂独立登记。`*-latest` 等可变别名或 API 同名更新不证明权重版本固定；即使返回身份相同，仍须披露服务端漂移风险。跨模型、问法、任务、自然/合成类型不得套阈值。
4. 第一次启用任一 validation 后，这个数据集禁止新增 dev 运行或重新登记策略。同一臂的 validation 只登记一个策略和输出目录；更换目录不能再试。网络失败保留，原目录仅能按原协议续跑，仍受原尝试次数约束。
5. `evaluate-policy` 写一次不可覆盖的留出评价。再次调用只返回原评价，不用更换后的标签重新打分；提前评价、执行缺失或标签不全都会如实保存为不完整，不能借此打开 test。应先核对完成状态和标注，再做此步骤。
6. test 在同一策略 validation 已完整评价后才可启用，同样一次运行登记和一次评价。留出统计不接收临时 `--threshold`；旧 `score` / `evaluate` 只用于 dev。
7. 登记使用数据集目录中的 `.semantic-governance`，包含原输出路径；保留并随数据集一同归档。它是防误操作和重复调参的本地账本，不是访问沙箱或加密封存。文件所有者仍能复制/改文件；不得把手工删账本、换数据集身份或预先登记大量近似臂当独立验证。

失败、不完整和人工分歧保留，不用重跑成功覆盖历史。若不得不变更协议，先说明原因和已看过哪些数据，使用新的预注册实验与真正未见的留出材料；不能把同一数据换名当新测试集。

## 效果和费用边界

请求数、失败尝试、缺失 usage、API 原字段用量、请求延迟总和与记录日历耗时分别报告。不同字段可能包含重复口径，不能将缓存明细与总输入再相加。没有账单不编美元；没有真实模型调用不宣称供应商增量、语义收益、净节省时间或成本优势。
