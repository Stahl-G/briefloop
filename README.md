# BriefLoop

一个面向 macOS 的个人本地简报工具：从来源生成简报，独立评分，直接改稿，再从修订中整理经验、改进后续任务。

## 启动

只需要 clone **BriefLoop 这一个仓库**，不需要再 clone WikiSkill，不需要手动安装它，也不需要构建前端。

```sh
cd briefloop
./start.sh
```

首次启动自动建立 `.venv`、安装随仓库提供的 WikiSkill wheel 和其他 Python 依赖、启动本地服务并打开浏览器。后续再次执行会复用环境和已有服务。

前提是本机有 Python 3.11+；生成简报使用已安装、登录且支持原生子 agent 的 Codex CLI，认证和服务商沿用本机 Codex；模型与推理档位在页面上显式选择，默认 Luna / high，不再隐式继承高价模型。不修改全局配置。首次安装普通依赖需要网络。

可选：`./start.sh --workspace /path/to/workspace --no-open`。端口默认自动选择；指定 `--port 8765` 可固定端口。关闭网页不停止后台任务。

## 对话工作台

主页提供持久会话、消息输入、文件附件、模型与推理档位选择，以及真实的工具与子 Agent 活动。发送消息会启动所选模型；默认 Luna / high。仅打开网页或新建空会话不调用模型。

- 空闲时发送直接开始一轮；运行中可以选择排队，或将补充要求发送到当前轮次。界面显示“已送达”表示 Codex 接受了输入，不能保证模型已经执行了要求。
- “停止”中断当前会话，并取消尚未执行的排队消息。关闭网页后服务仍运行；回来后从保存的会话继续查看。
- 上传文件后可随消息附加，文件也进入工作区来源列表。模型收到本地材料路径。
- 简报生成、评分与 Wiki 学习通过同一个 Codex app-server 接口执行，在会话中查看进度、补充要求；简报正文和评分保留在产物视图。
- 会话与公开活动保存在工作区数据库；不在页面显示模型的私有推理。断线不会自动重发已经送出的消息。

后端直接使用本机 Codex CLI 的 `app-server`，不需要额外模型 API key 或第二个仓库。升级服务前请先等待正在运行的旧任务完成；旧 `codex exec` 任务不能无缝接管为双向会话。

## 工作区、模型和权限

侧栏的工作区入口可打开已有文件夹或新建空工作区；每个目录分别保存会话、来源、稿件、Wiki 和设置。打开空目录不会自动调用模型，先输入目标或上传材料即可。切换不会停止另一个工作区的任务。启动一个尚未运行的已有工作区时，旧排队任务保留供手动恢复，自动学习暂不启动；在设置中明确开启自动学习后恢复该功能。

“设置”集中管理主模型、角色模型及学习轮数。Evaluator、Wiki Maintainer、Skill Proposer 可分别选模型与档位，未选则继承主链。模型配置在提交任务时保存，后续修改不改变已提交的任务。Evaluator 提供单稿评分和产物比较两种模式，共享角色模型设置，每次使用独立会话及原生子 agent；选择另一模型可以减少部分同模型偏差，但评分仍须核对原文，不能据此保证正确。

聊天输入区提供只读或工作区读写权限；权限在下一轮生效，向当前轮补充要求不会变更它。联网单独选择。正式生成/评分/学习需要保存产物，因此专用工作流会话使用工作区读写。上下文信息来自 Codex 的实际统计；没有窗口上限时显示未知，不用累计多轮费用 Token 冒充当前占用。

## 可选 Tavily 检索

“材料与需求”的联网开关下可直接展开 Tavily 配置，设置页也能管理同一组控件。默认使用 Codex 原生搜索；切换 Tavily 后填写自己的 API key。保存密钥只写本机，不会验证或执行收费搜索；真正执行检索会消耗 Tavily 账户额度。

后端优先读取 `TAVILY_API_KEY`，否则读取 `~/.config/briefloop/tavily.key`（仅本机用户可读写）。密钥不写入工作区、会话、Wiki、技能或 API 响应。移除本机保存的密钥不会改变环境变量。

Tavily Search 与 Extract 通过 BriefLoop 自带 Python 接口调用，无需另装 Tavily CLI 或 clone 第二个仓库。启用联网并选择 Tavily 的新任务，会把内置 Tavily 技能正文注入检索 Scout；关闭时不注入。该技能按官方 Search/Extract 文档编写，使用 BriefLoop 的来源登记工具；它不是未经修改的官方 CLI skill。搜索摘要只用于发现 URL，先直接下载网站原材料，必要时再用 Extract。Tavily Extract 返回的是提供商提取文本，页面会明确标注；不会当成原网站字节，也不使用 Tavily Research 生成的报告作为原材料。

联网抓取的新来源保存原始响应、提取正文和抓取记录，来源面板可下载。历史来源没有原件时如实保留缺失。Wiki 页分别展示已启用技能与待验证候选；候选已生成但学习暂停时，仍可展开阅读，继续验证须明确启动模型任务。

## 使用

1. 在“需求与来源”填写用途、读者、篇幅和时间范围，上传材料。需要时开启联网补充。
2. 点击生成前确认页面显示的模型和档位；调用会消耗相应账户额度或 API 费用。生成后直接看稿；Evaluator 独立完成四项评价，问题可查看来源。低分不隐藏稿件。
3. 直接编辑正文和表格，自动保存修订并保留原稿。也可留下评论。
4. 在反馈面板调整“WikiSkill 最多演化轮数 K”，默认 1。更多轮数可能消耗更多 Token，未必更好。
5. 开启自动学习后，服务端在编辑静默约 30 秒后合并反馈；也可立即处理。当前学习期间的新反馈进入下一批。
6. Wiki 页面查看经验与技能版本；学习任务可看比较、停止和恢复。候选更好则自动用于下一轮，随时回退。

试验生成稿不混入正常稿件列表；可以在“查看比较”中读到旧稿与候选稿。评分只对应其具体版本，用户改稿后不沿用旧分数。

## 状态和恢复

```sh
.venv/bin/briefloop status --workspace ./workspaces/default
.venv/bin/briefloop doctor --workspace ./workspaces/default
```

服务日志在工作区 `server.log`。每项任务的 `jobs/<id>/` 保存实际 prompt、native agent 记录、输出和使用量。失败或中断后从页面恢复，复用已完成产物；如果改了模型，则创建新执行，不恢复旧模型子 agent；评分失败可以只重新评分。服务/电脑停止时运行会停止或等待恢复，系统不会声称离线仍在执行。

来源和稿件在 SQLite/本地文件中保存，请备份整个工作区。运行数据、凭据和私有计划不进 Git。仅监听本机 loopback；不是多用户托管服务。

## WikiSkill 与扩展

普通用户只使用这一个 BriefLoop 仓库。`vendor/wheels` 随项目提供 WikiSkill 的已构建依赖包，启动时自动安装。WikiSkill 的开发源码另行维护，BriefLoop 不包含第二套源码 checkout；反馈学习扩展归该依赖，应用只保留适配代码。保留原数值评分流程及历史研究结果。

默认可演化角色为 Scout、Analyst。`briefloop.skills.register_target(store, role_id, instruction)` 可注册其他角色；同一技能绑定、任务注入和反馈学习路径会携带这些角色。Evaluator 的评价规则保持独立，不能用自己改过的标准证明自己变好。

## 开发

网页编辑器资源已打包。每次服务启动同时加载该版本的前端与后端；构建后需在任务空闲时重启服务。改前端时：

```sh
npm ci
npm run build
.venv/bin/python -m pip install -e '.[dev]'
.venv/bin/python -m pytest -q
```

只保留核心行为测试，不移植旧项目的千级测试，也不把模拟评分当作实际改进。

早期执行方式曾完成一次真实闭环：Scout → Analyst → Scorer → 网页改稿 → Maintainer → Proposer → 候选执行与独立比较。合成案例的结果为平局，因此保留基础技能并保留 Wiki；没有把更高的单次评分当作已证明的改善。四个核心行为测试及单仓库启动检查通过。该样例不代表跨任务效果或统计结论。

本轮交互改造另行验证了页面操作、消息/权限/模型路由和打包资源。已观察用户发起的真实 Luna 聊天回复；新增 Tavily 接口以离线模拟响应验证，未进行真实收费请求。上述早期学习案例不代表本轮改造后的完整学习链已重新实测。
