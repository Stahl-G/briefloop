# 跨平台版本一致性检查

运行 `python scripts/check_versions.py` 时，目标版本始终读取当前仓库 `pyproject.toml`。检查不内置任何发行版本号。

默认检查 Python 版本声明、共用的 Mac/Windows Electron 配置、npm 锁文件和静态网页版本。CI 还会执行本次安装的 CLI，并核对构建 wheel 的元数据。

## 发布前

```sh
python scripts/check_versions.py --cli /实际安装路径/briefloop --wheel /本次构建的包.whl
```

Mac 上加入 `--mac-app /Applications/BriefLoop.app`，读取 App 的 Info.plist、内置 backend manifest 和 wheel 元数据，并核对 wheel 哈希。

Windows 上加入 `--windows-app 'C:\实际安装目录\BriefLoop.exe'`。必须在 Windows 本机读取 EXE 的 ProductVersion；同时核对相邻 resources/backend 内的 manifest、wheel 元数据及哈希。传入安装后或解包后的程序，不是 NSIS 安装器。缺文件或权限错误会失败，不能只凭文件名判定版本。

## 发布后

加入 `--pypi` 查询官方 PyPI 最新版本；同时传 `--wheel` 时，要求 PyPI 上存在同名、同 SHA256、未撤回的 wheel。

不同系统分别将 JSON 输出保存后，可汇总原生核验结果：

```sh
python scripts/check_versions.py --platform-report mac.json --platform-report windows.json --pypi --require-all
```

只有源码和 CLI、Mac、Windows、PyPI 四项实际记录都匹配，`all_platforms_consistent` 才为 `true`。未提供的通道显示 `unverified`；`--require-all` 将未核验也视为失败。异版平台记录不能混入本次报告。不要修改记录中的版本字段来使检查通过。

发布前不要求 PyPI 已有待发布版本。分批发布时允许先上传 Python 包，但发布后的完整核对必须如实报告桌面包滞后；源码版本一致不等于安装包已重新发布，也不代表用户本机已升级。
