# 真实宿主验收记录

这里记录在真实 CLI 宿主上跑过的端到端验收：做了什么、观察到什么、没有覆盖什么。只记录实际执行过的运行，不把源码分析或替身测试写成验收。

## 2026-09-16：Opencode 并行审阅与正式交付

环境：macOS 15（Apple Silicon）；opencode 1.18.30；执行后端 `opencode`，模型 `opencode/muse-spark-1.3-contributor-free`；BriefLoop 源码为当时的集成分支；临时工作区，两份合成材料（各一段中文文本），离线任务（`allow_web=false`），研究深度 quick，目标 350 字。

| 步骤 | 观察到的结果 |
| --- | --- |
| 两份报告同时生成（`max_reports=2`） | 04:11:06 同时开始，A 04:15:45 完成，B 04:19:57 完成，时间窗重叠 |
| 企业内部报告 A 的独立审阅 | 生成过程中自动运行并完成（04:14:43 → 04:15:19），Reviewer 只读固定核查包 |
| 两份报告同时独立审阅 | 04:19:59 两个审阅任务同时处于 running |
| 同一报告再次请求审阅 | 返回正在运行的同一个任务，没有并行开第二个 |
| 取消其中一份 | B 在 04:20:04 取消（"任务已停止，已生成内容保留"），A 不受影响，04:20:37 完成 |
| 正式交付门禁 | A 的 `eligibility.eligible=true`，无阻断项；3 条提示（1 条缺口披露、2 条数值未检查） |
| 正式交付 | 04:21:30 → 04:21:32 完成，产出 `report.docx`（36 KB）、`manifest.json`、`records.json` 和核查包；manifest 绑定 `review_id` 与 `review_fingerprint` |
| 交付件内容 | 正文分节、逐句带 `[1]` 引用、文末来源列表指向 `synthetic-A.txt` |

未覆盖：

- 本次审阅没有产生 finding，所以"处理审阅问题后再交付"（`/api/review-response`）这一步没有被实际执行。
- 合成材料短、报告 350 字、模型为免费档；这不能代表长报告、多来源、联网研究或付费模型下的表现，也没有测量 token 与费用。
- 没有做事实核查（`fact_check`）路径、定时报告路径和桌面 App 内的操作。
- 取消发生在审阅开始约 5 秒后；没有覆盖长时间运行后取消、或宿主异常退出的情况。

## 2026-09-16：桌面 PDF 导出（真实 Electron）

环境：Electron 44.3.0 / Chromium 152.0.7977.78（与 `desktop/electron/package.json` 锁定版本一致）。运行 `npm run verify:pdf`，在真实 Electron 主进程里执行与产品相同的导出代码。

结果：生成真实 PDF（`%PDF-1.4`，2 页，约 56 KB）；页面内的外部图片与 `fetch` 均未发出请求；`javascript:false` 下脚本无法执行；导出后无残留窗口与临时文件；取消保存不写文件；并发导出被拒且第一份仍完成。人工用 `pdftotext`／`pdfinfo` 与渲染页面确认标题、表格、内联图片正常，被拦截的外部图片显示为占位符。

未覆盖：没有在打包后的桌面 App 里用鼠标点击导出，系统另存对话框的外观与 Dock 行为未验收。

## 2026-09-16：内置引擎与 Opencode 同包同模型审阅对照

环境：macOS（Apple Silicon，接电源、开盖，`caffeinate -i`，运行期间 `pmset` 无睡眠记录）；Node 25.6.1；opencode 1.18.30；模型 `deepseek/deepseek-v4-flash`，推理档 high，DeepSeek 官方 API。两个运行时同时启动，各自复制同一个真实工作区（企业报告验收工作区），审阅同一冻结版本 `brief_a56c592a9aaf461d_r1`（它有 5 条针对本版的作者回应）。HOME 指向空目录，模型凭据只来自 `DEEPSEEK_API_KEY` 环境变量；代理环境变量已去掉。脚本：`native-engine/experiment_ab.py`。

| | 内置引擎 `briefloop-native` | `opencode` |
| --- | --- | --- |
| 结果 | 首次回复未通过结构校验（`requirement_checks` 多出 `basis` 字段），按校验错误重答一次后接纳，review `complete` | 首次回复即接纳，review `complete` |
| 墙钟时间 | 364 秒（模型请求合计 359 秒） | 252 秒（模型请求合计 244 秒） |
| 工具调用与模型请求 | 45 次 `packet_read`、1 次 `packet_list`，共读回约 87 万字符；28 次模型请求 | 34 次 `read`，共读回约 79 万字符；25 次模型请求 |
| 生成 token（含思考） | 7.05 万，其中思考 4.53 万 | 3.90 万，其中思考 2.90 万 |
| 回应核对 | 5 条：4 条 resolved、1 条 unresolved | 同样 5 条，逐条结论一致 |
| 主张核对 / 条款核对 | 6 条均 supported_for_scope / 21 条 | 6 条均 supported_for_scope / 21 条 |
| 发现 | 7 条（2 major、5 minor） | 2 条 minor |
| 未核验事项 | 4 条 | 5 条 |
| 总评 | 建议修改 | 建议修改 |
| 费用（各自价目表） | 0.082 美元（未缓存输入 34.5 万、缓存读 489 万 token） | 0.078 美元（未缓存输入 27.7 万、缓存读 421 万 token，取自 opencode 会话记录）；两边价目表不同，按同一份价目表换算，内置引擎贵约三到四成 |

耗时差异的构成（按两边会话记录逐次请求核对）：引擎自身开销约 1 秒，读文件耗时可忽略；两边生成速度相同（长回复约 230 token/秒），多出的时间几乎全部来自多生成的 3.1 万 token。其中约 1.1 万是结构校验失败后整份 JSON 重写（36 秒）；约 0.5 万是发现更多导致的最终 JSON 更长；约 1.6 万是审阅中途思考更多（3 次长思考分别用了 54、39、33 秒）。推理档位不是原因：opencode 会话记录的 variant 为 `default`，但对 DeepSeek 官方 API 单独对照（同一问题各 3 次），不传 `reasoning_effort` 与 `high` 的思考量相当（均值约 1.2 万与 1.0 万 token），同一设置下单次思考量可相差 2.4 倍。

两边共同发现：8 月 20 日、24 日的量比引用了工作簿，但数值只在图表数据文件里；正文主张绑定只覆盖少数段落。内置引擎另外报告了若干问题，其中一条已人工核对属实：业绩公告写 2025 年末现金及受限现金 5,890 万美元，电话会记录第 92 行写 “[ $85.9 ] million”，报告没有登记这一差异。图像输入两边不对等：opencode 的首条消息带了 4 张报告图（PNG 附件），DeepSeek 是否实际接收未核实；内置引擎不发送附件（`NativeHarness` 收到的视觉来源只做存在性校验），它用 `packet_read` 读图，pi 按该模型为纯文本丢弃了图片，于是把“附图未目视核验”列为核心未核验事项。另外，任务提示是为 Codex/opencode 宿主写的，多处与内置引擎不符（声称图片会作为附件发送、“只有 read 工具”、绝对路径、长行截断说明），本次未改提示。

未覆盖：

- 每边只跑了一次，发现条数、思考量和耗时的差异都不能当作稳定结论；除上面那一条以外，其余 major / minor 发现未逐条人工核对。
- BriefLoop 请求的 variant `high` 在 opencode 会话里记为 `default`，原因未单独排查；对 DeepSeek 没有影响，对默认档位不同的 provider 可能有影响。
- 没有测支持图像输入的模型，也没有测长时间卡流后在同一会话里重试的真实场景（替身测试已覆盖）。
- 内置引擎尚未出现在界面中，本次通过脚本直接排入审阅任务，没有经过页面操作和正式交付。

## 2026-09-17：内置引擎与 Opencode 同批 5 对 5 审阅对照

目的：判断内置引擎能否作为推荐的独立审阅后端。四条标准在运行前定好：被接纳比例不低于 Opencode；耗时中位数不超过 Opencode 的 1.1 倍；按同一价目表算的平均成本不超过 1.1 倍；两个已人工核实的问题检出次数不少于 Opencode。

环境：macOS（Apple Silicon，接电源，`caffeinate -i`）；opencode 1.18.30；模型 `deepseek/deepseek-v4-flash`，推理档 high，DeepSeek 官方 API。10 个进程在 13:42 同时启动，每个复制同一工作区、审阅同一冻结版本 `brief_a56c592a9aaf461d_r1`，各用独立的空 HOME，并预置 opencode 模型清单。凭据只来自环境变量。源码冻结在提交 fbd6c38e：内置引擎提供包内搜索、分段读取、主张追溯、计算和带校验的提交，系统提示词分层装配。两边共用的审阅要求点名了“图上文字与数据对照”和“同一指标跨来源核对”。脚本：`native-engine/experiment_ab.py`。成本按输入 0.22、输出（含思考）0.66、缓存读 0.007 美元/百万 token 统一计算；opencode 的用量取自它自己的会话库。

两个已知问题：
- **图表脚注矛盾**：图 `fig_dc483082d36b4165` 的 PNG 脚注写“8 月无单日量比≥1.5x 的放量交易日”，与同图标注、data.csv 和正文“3 个放量日”矛盾。
- **现金口径不一致**：2025 年末现金及受限现金，业绩公告写 5,890 万美元，电话会记录写 [ $85.9 ] million，正文未交代差异。

脚本按文本匹配标出检出，下面每条检出都已逐条读原文确认；未标出的审阅中，也没有以其他说法提到这两个问题。

| | 被接纳 | 耗时中位数（均值） | 同表平均成本 | 模型请求（均值） | 生成 token 均值（含思考） | 图表脚注矛盾 | 现金口径 | 结构纠正轮 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

按预定标准：被接纳比例持平；成本为 Opencode 的 0.95 倍，通过；两个已知问题的检出次数更多，通过；**耗时中位数为 Opencode 的 1.14 倍，超过 1.1 倍，未通过。** 因此内置引擎继续作为实验选项，不作为推荐或默认的审阅后端。

多出的时间主要来自更多轮模型请求（平均 54 对 34）和更多生成 token（6.7 万对 5.2 万）。内置引擎平均每次读文件 51 次、搜索 19 次，Opencode 读 40 次。有一次内置引擎第一次提交被结构校验退回，只改出错字段后通过，没有触发整份重写。

未覆盖：
- 只有一个核查包、一个模型，每边 5 次。
- 除两个已知问题外，其余发现没有逐条人工核对，发现数量不作为质量结论。
- 本次共用审阅要求比上一次对照多了两类核查说明，结果不能和 9 月 16 日那组直接比较。
- 没有覆盖支持图像的其他模型，也没有经过页面操作和正式交付。

## 待执行：Windows 桌面生命周期（#734）

需要一台 Windows 11 x64 和打包后的桌面版（后端与桌面壳同版本）。每步记录 BriefLoop 版本、Windows 版本、宿主 CLI 版本，以及进程列表或截图。

1. 新建空目录并打开为工作区；欢迎页能检测到运行环境。
2. 在材料里粘贴一个网址读取：成功保存来源，过程中不弹出命令行窗口，任务不停在"正在读取"。
3. 上传一份 10 页以上的 PDF：抽取完成，能看页图。
4. 设置 → 运行时检测：列出本机已安装的宿主与版本，未安装的标为未安装。
5. 切换到另一个工作区目录：原工作区后台停止，新工作区打开，原窗口内容已保存。
6. 生成一份短报告；生成过程中在任务管理器里确认子进程（python、宿主 CLI、必要时 curl / pdftotext）存在。
7. 用任务管理器强制结束桌面进程：确认后台 Python 服务及其子进程在数秒内退出，没有孤儿进程残留（这正是 #718 / #734 的所有权管道要保证的）。
8. 重新打开同一工作区：未完成的任务显示为已中断可恢复，正文与来源都在，恢复后能继续。

判定：第 2、3、4、6 步都不因为子进程继承桌面所有权管道而卡住；第 7 步没有残留进程；第 8 步没有丢内容。任何一步失败都记录当时的进程列表和日志（按 CONTRIBUTING.md 只分享已检查的必要日志）。
