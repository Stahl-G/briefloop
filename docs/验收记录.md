# 真实宿主验收记录

这里记录在真实 CLI 宿主上跑过的端到端验收：做了什么、观察到什么、没有覆盖什么。只记录实际执行过的运行，不把源码分析或替身测试写成验收。

## 2026-09-16：Opencode 并行审阅与正式交付

环境：macOS 15（Apple Silicon）；opencode 1.18.30；执行后端 `opencode`，模型 `opencode/muse-spark-1.3-contributor-free`；BriefLoop 源码为当时的集成分支；临时工作区，两份合成材料（各一段中文文本），离线任务（`allow_web=false`），研究深度 quick，目标 350 字。

| 步骤 | 观察到的结果 |
| --- | --- |
| 两份报告同时生成（`max_reports=2`） | 04:11:06 同时开始，A 04:15:45 完成，B 04:19:57 完成，时间窗重叠 |
| 企业内部报告 A 的独立审阅 | 生成过程中自动运行并完成（04:14:43 → 04:15:19），Reviewer 只读固定核查包 |
| 两份报告同时独立审阅 | 04:19:59 两个审阅任务同时处于 running |
| 同一报告再次请求审阅 | 返回正在运行的同一个任务，没有并行开第二个 |
| 取消其中一份 | B 在 04:20:04 取消（"任务已停止，已生成内容保留"），A 不受影响，04:20:37 完成 |
| 正式交付门禁 | A 的 `eligibility.eligible=true`，无阻断项；3 条提示（1 条缺口披露、2 条数值未检查） |
| 正式交付 | 04:21:30 → 04:21:32 完成，产出 `report.docx`（36 KB）、`manifest.json`、`records.json` 和核查包；manifest 绑定 `review_id` 与 `review_fingerprint` |
| 交付件内容 | 正文分节、逐句带 `[1]` 引用、文末来源列表指向 `synthetic-A.txt` |

未覆盖：

- 本次审阅没有产生 finding，所以"处理审阅问题后再交付"（`/api/review-response`）这一步没有被实际执行。
- 合成材料短、报告 350 字、模型为免费档；这不能代表长报告、多来源、联网研究或付费模型下的表现，也没有测量 token 与费用。
- 没有做事实核查（`fact_check`）路径、定时报告路径和桌面 App 内的操作。
- 取消发生在审阅开始约 5 秒后；没有覆盖长时间运行后取消、或宿主异常退出的情况。

## 2026-09-16：桌面 PDF 导出（真实 Electron）

环境：Electron 44.3.0 / Chromium 152.0.7977.78（与 `desktop/electron/package.json` 锁定版本一致）。运行 `npm run verify:pdf`，在真实 Electron 主进程里执行与产品相同的导出代码。

结果：生成真实 PDF（`%PDF-1.4`，2 页，约 56 KB）；页面内的外部图片与 `fetch` 均未发出请求；`javascript:false` 下脚本无法执行；导出后无残留窗口与临时文件；取消保存不写文件；并发导出被拒且第一份仍完成。人工用 `pdftotext`／`pdfinfo` 与渲染页面确认标题、表格、内联图片正常，被拦截的外部图片显示为占位符。

未覆盖：没有在打包后的桌面 App 里用鼠标点击导出，系统另存对话框的外观与 Dock 行为未验收。

## 待执行：Windows 桌面生命周期（#734）

需要一台 Windows 11 x64 和打包后的桌面版（后端与桌面壳同版本）。每步记录 BriefLoop 版本、Windows 版本、宿主 CLI 版本，以及进程列表或截图。

1. 新建空目录并打开为工作区；欢迎页能检测到运行环境。
2. 在材料里粘贴一个网址读取：成功保存来源，过程中不弹出命令行窗口，任务不停在"正在读取"。
3. 上传一份 10 页以上的 PDF：抽取完成，能看页图。
4. 设置 → 运行时检测：列出本机已安装的宿主与版本，未安装的标为未安装。
5. 切换到另一个工作区目录：原工作区后台停止，新工作区打开，原窗口内容已保存。
6. 生成一份短报告；生成过程中在任务管理器里确认子进程（python、宿主 CLI、必要时 curl / pdftotext）存在。
7. 用任务管理器强制结束桌面进程：确认后台 Python 服务及其子进程在数秒内退出，没有孤儿进程残留（这正是 #718 / #734 的所有权管道要保证的）。
8. 重新打开同一工作区：未完成的任务显示为已中断可恢复，正文与来源都在，恢复后能继续。

判定：第 2、3、4、6 步都不因为子进程继承桌面所有权管道而卡住；第 7 步没有残留进程；第 8 步没有丢内容。任何一步失败都记录当时的进程列表和日志（按 CONTRIBUTING.md 只分享已检查的必要日志）。
