# 研究目的、上下文与方法

标准报告的「研究选项 → 研究方法」和新建报告表单提供两种选择：

- **分轮研究**（默认，`guided`）：沿用现有侦察、聚焦与补缺建议。
- **按目标补证**（试用，`goal_driven`）：从读者问题与现有证据出发，决定继续、集中处理一个冲突、换已授权来源或停止。材料充分时无需额外检索；不按周报/月报凑 Scout 数，不强制第一批查询数或执行三轮。

选择只对本报告生效，创建任务后保存在 requirements；恢复沿用原选择，旧任务缺少此字段仍走原策略。快速模式有自己的生命周期，本选项不改变快速模式行为。试用不是质量优势的承诺，也不会自动切换现有报告。

## 给角色的上下文

`task_context` 是对既有任务包的阅读导航：purpose（目的）、knowledge（证据和未知的入口）、method（方法建议）、boundaries（实际边界）。它不创建新的事实摘要、知识库、权限或评分结果。

主 Agent 看读者目标、来源索引、当前研究交接和实际预算；Scout 只拿分配的问题、当前交接、来源入口和对应检索技能；Analyst 看当前证据/缺口、读者要求与写作技能；Evaluator 独立看实际正文、原文及保存时/当前研究状态，不接收检索技能，也不把作者的解释当事实证明。CLI 通过文件读取，内置引擎通过任务包读取，语义一致。

原始用户要求、来源快照和版本仍是权威。研究中的新认识可以通过原有研究交接和缺口更新推进；不会改写旧稿保存的研究状态。Wiki/历史稿属于经验和背景，不充当本期证据。

## 保留的控制

共享预算、最大轮数、并发和渠道权限保持不变。深度目标研究不预分配未用 Scout/轮次，但仍受所选深度最大轮数约束。收轮必须在既有 summary（或 early_stop_reason）说明继续/停止依据；程序检查记录存在，不替模型判定证据充分。已承诺的 Scout 仍须有结果或失败/跳过原因。写前交接与收轮、来源定位、稿件版本、独立评价/审阅、最多一次自动修订和正式交付门禁不变。

本轮没有做质量对照；小型合成闭环用于验证真实运行，不能证明报告更好、减少 Token 或加快执行。以后可在冻结材料和同一模型下分开比较上下文与策略的效果。
