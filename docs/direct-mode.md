# 直写模式（试用）

`completion_mode=direct`：一个作者在同一上下文中检索、阅读并写完整份报告；保存后再做原文定位、确定性检查、独立评价/审阅和最多一次自动修订。

## 为什么

2026-10-10 的六题实验加了“同模型纯 Codex”基线臂。在同一冻结评分标准下，纯 Codex 六题都不低于 BriefLoop 分轮/目标两臂（不含交付项 83.5–88 对 71.5–83.9），用时约为五分之一到十分之一。复盘原因：

1. 跨来源推理需要证据同时在一个上下文里；Scout→交接→Analyst 的拆分会丢掉这类推理。
2. 写作前大量流程与合规规则占用注意力，评价也只奖励谨慎和覆盖。
3. 研究方法和“怎样才算答完”的上下文不足；纯 Codex 在三题主动加载了领域技能。
4. 默认期间/篇幅等先验错误（期间默认“今天”曾把 Tavily 检索锁在一天内，已另行修复）。

强模型已经能可靠地检索和写作。BriefLoop 应把价值放在单次会话做不到的事：持久来源快照与版本绑定、独立审阅、跨期连续性、方法库与学习、交付治理。

## 做了什么

- 写作回合带计量工具：`web-search`、`add-url`、`read-source`，共享本任务预算；来源经 `add-url` 自动登记，正文用 `[@source_id]` 引用。
- 提示只给任务、完成标准思路、引用和日期规则、篇幅空间，不加载完整研究协议、Scout 合同或写前对照。
- 保存后复用快速稿的后台链路：只对作者实际引用的来源做原文定位，随后评价；与快速稿不同，保留独立审阅和一次自动修订。
- 未登记的引用标记被移除并写入研究记录，不让虚构来源进入正文。

## 边界

- 暂只支持能调用本地工具的 CLI 宿主（Codex、OpenCode、bridge）；内置引擎需要先给作者回合挂上计量检索工具。
- 不派 Scout，不产生逐题覆盖记录；覆盖与停止理由的工具记录关联是后续工作。
- 现有标准、快速流程不变，可随时选回。是否成为默认，需在冻结材料上与纯 agent 基线及标准流程再比较。
