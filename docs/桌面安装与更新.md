# 桌面安装与更新

BriefLoop 0.20.0 的桌面 App 与 WebUI 共用报告、材料、模型设置和本地工作区。桌面增加工作区选择、Word 另存、保存后退出及 App 更新入口。

## 选择安装方式

在 [GitHub Releases](https://github.com/Stahl-G/briefloop/releases) 下载对应资产：

| 系统 | 安装包 | 安装方式 |
| --- | --- | --- |
| macOS Apple Silicon | `BriefLoop-0.20.0-arm64.dmg` | 打开 DMG，将 BriefLoop 拷入 Applications，运行已安装的 App。 |
| Windows x64 | `BriefLoop-Setup-0.20.0-x64.exe` | 运行安装程序，选择当前用户的安装目录。 |

首批桌面包未做 macOS 签名或公证，也未使用 Windows 代码签名。系统可能显示未识别开发者或发布者；核对下载来源与发行页的 SHA-256 后，使用系统提供的单个应用许可入口。不要关闭整个系统的安全设置。Intel Mac、Windows ARM 和 Linux 桌面包未列入首批发行。

需要 WebUI 时，可按 [README](../README.md) 使用源码或 PyPI 包，无需安装 Electron App。PyPI 提供 Python 服务，不包含桌面安装包。

## 首次准备环境

1. 打开 App，自动检测已有 Python 3.11 或更新版本。未找到时，按页面入口安装 Python，再重新检测。
2. 点击“下载依赖并准备”。App 使用随包 BriefLoop wheel，在自己的用户数据目录创建独立 Python 环境。
3. 页面依次显示环境创建、依赖安装和验证等实际阶段。完成后新建工作区，或打开已有工作区目录。
4. 在设置中选择已安装、已认证的模型 CLI 与模型；也可先导入无需模型的合成示例。

App 不自动安装系统 Python，不向全局 Python 安装依赖。首次准备依赖需要访问 PyPI。使用较新的 Python 而依赖尚无匹配 wheel 时，准备会失败；可安装依赖支持的 Python 版本后重试。

Electron 已包含运行桥接需要的 Node。无需另外为 BriefLoop 桌面桥接安装 Node；所选模型 CLI 自身的安装要求仍遵循该 CLI。WebUI 的桥接宿主需要本机 Node.js 20+。

准备期间可取消。取消会等待属于本次准备的进程结束，保留既有环境及工作区；失败后依界面提示重试。原件、报告与用户配置不属于临时安装文件。

## 保存、Word 与退出

在报告页编辑并保存正文，点击生成 Word；完成后通过原生“另存为”选择位置，再使用 Word 或 WPS 阅读。下载对应已保存的版本，界面上的未保存修改需要先保存。

关闭 App 会先请求保存。任务仍在运行时，可选择继续工作，或停止任务并退出。保存或停止失败时窗口保留，显示实际错误。桌面只管理本窗口启动的工作区服务；不会按程序名称批量关闭其他 Python、Node 或模型进程。

WebUI 的行为有所不同：关闭浏览器标签页不会停止独立启动的后台服务。

后台采用按需运行：Codex、OpenCode 和通用 CLI Bridge 没有活动回合、子任务、事件订阅或在途请求时，空闲 30 秒回收进程；后续使用按需重新启动。原生会话 ID 保存在工作区，支持续接的宿主可恢复原会话。任务队列空闲时降低查库频率，同服务提交会唤醒队列，其他进程提交最多等待 5 秒被发现。正在执行的报告不受这些空闲间隔限制。网页可见且无任务时每 15 秒检查状态，隐藏时每 60 秒检查；回到前台立即刷新，有活动任务时恢复原来的快速轮询。

BriefLoop 不会仅因长时间没有鼠标或键盘操作就自动退出。未保存的编辑、正在执行的任务和外部 Agent 的调用仍需保留；要结束桌面后台，请正常退出应用。主动启动的 CLI `serve` 持续提供服务，直到用户停止它。

## 更新版本

打开“设置 → 版本更新”：

1. 检查官方 GitHub Release。页面显示当前版本、可用版本或请求失败信息。
2. 有可用安装文件时开始下载，查看真实下载进度。
3. 下载完成后，由你发起安装。App 先保存修改，并处理当前工作区的运行任务。
4. macOS 使用 ZIP 更新载荷，校验并解压后打开 Finder 更新文件夹。退出 App 后，将 BriefLoop 拖到旁边的 Applications 替换原应用，再启动。Windows 将安装请求交给原生安装程序。

Mac 官网首次安装仍使用 DMG；应用内更新使用同一冻结构建产出的 `BriefLoop-<版本>-arm64-mac.zip` 和 `.zip.blockmap`。已有有效 ZIP 缓存时，只下载变化的块，再校验重建的完整文件；不承诺每次都能增量。首次无缓存、缓存损坏、服务不支持 Range 或变更太多时完整下载，界面显示原因。保留一份已校验基准供下次复用，新基准保存后清理旧基准与其解压预览；不清理用户下载目录或报告。

已安装的旧版 DMG 更新器不能通过发布一个 ZIP 自动获得新能力，需先安装含此改动的新 App。手动安装 DMG 不会建立 ZIP 字节缓存，因此切换后首次应用内更新仍可能完整下载。此流程保留用户手动替换，不等于已签名的自动安装或后台静默更新。

正式 App 使用固定的官方来源，不自动下载降级版本，不在退出时偷偷安装。网络错误、发布资产缺失或下载校验失败会留在更新页面；可根据提示重试。正在运行的源码服务不会因更新文件而热替换。

开发时的本地更新源会明确标记，仅用于受控验收。它与 GitHub 公开更新源不同；公开更新需要发行页实际包含对应安装文件和平台更新元数据。

## 报告数据

工作区目录保存对话、原件、稿件、评价与 Wiki。备份时复制整个目录。安装 App 与选择工作区分开进行，不要把工作区放进 App 安装目录。

正式发布前不提供跨历史架构的工作区迁移工具。保留旧目录，使用新工作区导入需要的材料；不要用安装文件覆盖数据目录。
