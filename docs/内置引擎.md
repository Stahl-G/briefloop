# BriefLoop 内置引擎

当前为开发分支功能。后端、前端和自动化验证已接通；本轮按用户要求暂缓真实模型调用、Computer Use 与 Mac/Windows 安装包验收。源码完成不代表已发布或报告质量已验收。

## 使用入口

在“设置 → 模型与提供商”选择“BriefLoop 内置引擎”。在 API 提供商表单选择用于内置引擎，填写 Provider ID、接口地址、API Key、模型 ID，然后保存并选用。支持表单中的 Chat Completions、Responses 和 Anthropic Messages 协议；不同提供商实际支持的接口和工具能力仍需短测试确认。模型格式为 `provider/model`，可从已配置目录选择或直接输入。

密钥保存在本机 `~/.config/briefloop/native-engine/providers.json`，权限为当前用户读写，不进入工作区、Git、报告、核查包或目录返回值。留空密钥可保留该模型已有密钥。同一提供商使用同一接口与密钥。环境需要 Node.js 22.19+；桌面可使用随壳提供的 Node 模式，不需要安装 OpenCode 或其他 Agent CLI。

聊天里仍可选模型和只读/读写权限。只读模式只允许读取和解释；读写模式可按用户要求创建报告、修订指定版本和安排导出。`/discuss` 只整理需求，不启动生成。模型服务商会收到本次实际提交的请求、上下文和工具结果；本地运行不等于材料不离开电脑。

## 共用流程

主 Agent 保存计划和读者契约，选择研究任务；Scout 使用相同的报告时间范围、角色技能、受控检索策略和共享预算，并行数服从冻结任务。研究宽度与同时执行数分别处理。后续轮次引用真实缺口，交接保留来源定位和待证状态，不把已引用当作事实核实。

研究结果通过现有 Scout 契约合并，写前对照使用现有 reconciliation 记录。Analyst 在独立材料上下文里完成富文本和表格，主链把已校验的草稿交给既有 Store 发布；普通下载、版本比较、独立审阅、一次自动修订及 WikiSkill 学习继续复用原流程。Reviewer 使用自己的固定只读核查包，不继承写稿工具或 MCP 凭据。MCP 材料读取仍依赖该报告已选择的连接器授权。

内置引擎没有宿主自带搜索；使用用户已经配置、且本报告已允许的受控渠道。不会为“能搜到”自行换渠道、加预算或调用其他 CLI。Analyst 不重新联网研究；图表和复杂文档能力以当前实际注册工具为准，不把未提供的任意 shell 能力写成已支持。

## 停止与恢复

一个内置引擎进程可管理多会话，取消只作用于目标任务及其子任务，不杀其他报告。等待 Scout/Analyst 不计作模型流卡死；停止会中断子工具等待。已接纳的来源、分段正文、计划、槽位结果和会话记录保留。

恢复时按原任务目录、槽位分工和冻结模型接回，已完成结果复用。相同对话回合的报告提交与回执在同一事务中保存，重试不会重复排队。用户并发修改继续由版本冲突规则保护。任务目标用时仍是软目标；只有明确设置的最长运行保护或用户停止会中断执行。

## 本轮验证边界

自动化使用合成材料、脚本引擎和本地假服务商，检查实际 Store/Worker/工具/版本链及引擎协议：并行研究、恢复不重跑、只读与禁网、停止传递、取消迟到结果、修订保留原稿、评价绑定、提供商配置、模型选择及密钥不回显。

这些检查不评价真实报告语义，也不证明真实服务商工具调用、视觉阅读、联网质量或原生桌面体验。待用户检查实现后，再安排实际验收。
