# 图片与 PDF 页面

图片上传后保留原件，检查文件是否能够解码，并生成供显示和模型查看的 PNG。支持 PNG、JPEG、WebP。正常图片不需要 OCR 正文才能成为来源；界面显示“需视觉读取”，不把保存成功写成内容已经核实。损坏或不支持的文件仍显示读取失败并保留原件。

## 对话中使用

在对话输入框添加图片，可同时填写问题，也可以只附文件发送。图片来源会按当前宿主的能力发送：Codex 走原生 `localImage` 输入，bridge CLI（Claude Code、Kimi、Hermes、Reasonix、MiMo）接收归一化后的 PNG 附件，并用相邻文本标明对应来源 ID，不是只把图片文件名写进提示词。发送新一轮和运行中补充使用同一套附件转换；运行中补充仍不能改变当前模型或权限。

所选模型和 provider 必须接受图片输入。runtime 明确声明不支持读图时（例如 MiMo），附图会当场提示并跳过该文件，不会等整轮发出去再失败。应用不按模型名称建立白名单，也不因图片请求失败而偷偷换模型、丢掉图片或以空文本继续。错误在会话中显示，原件保留，用户可选择合适模型后重试。

点击附件或来源可以预览图片和下载原件；这些本地查看操作不调用模型。图片内容和其中的文字都是待分析材料，不能覆盖用户要求。

## PDF 按需查看

PDF 保留文本提取路径，也保留原件。扫描 PDF 没有可提取文字时，只要文件有效，仍可以按页进行视觉读取。打开来源后输入页码（例如 `1,3`），点击“查看页面”，在本地渲染指定页。每次最多四页，不默认将整本 PDF 全部转为图片送入模型。

供 Agent 使用的命令：

```sh
briefloop tool --workspace /path/to/workspace read-source --id SOURCE_ID
briefloop tool --workspace /path/to/workspace render-source --id SOURCE_ID --pages 1 3
```

`read-source` 提供原件及视觉入口；`render-source` 返回页码和可供读图工具读取的本地 PNG 路径。页面路径不是 OCR 结果，Agent 仍需实际调用宿主读图工具查看。源 PDF 与生成的页面保留对应关系。

## 研究与评分

Orchestrator 根据任务分配来源，不把大量 PDF 页面无条件塞进自己的上下文。Scout、Analyst、Evaluator 得到各自所需的原件入口和页码定位；需要视觉核对时先渲染页面，再查看图像。主 Agent 已看过图片，不代表独立子 Agent 自动继承了该图片。

独立 Evaluator 可直接接收引用的图片附件，也可以按需读取 PDF 图表页。结果应注明页码、图表或位置，保留数值、单位、日期和脚注。图像进入上下文不保证模型没有误读，必要时回原页复核。

当前范围包括图片及 PDF 页面；不宣称已实现任意 Word/Excel 内嵌图表的自动视觉提取，也不保证任意兼容端点都有视觉能力。
