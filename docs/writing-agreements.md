# 写作约定与报告反馈

报告页右侧使用同一个输入框。点「发送」与 BriefLoop 讨论或修改本稿；想留下供 WikiSkill 验证的意见，点「留下经验」进入原有反馈表，遵循已设置的自动学习及预算；明确希望以后沿用的写法，点「下期沿用」直接保存。保存约定不启动模型学习任务，也不需要等待试写比较。

默认只适用于这份报告及通过「开始下一期」关联的后续报告；可以主动选择「本工作区所有新报告」。系统不根据标题相似猜测报告系列。已保存的约定可以展开查看并撤销；下一期草稿也可以取消勾选某条，只跳过本期。

约定在新任务创建时从本地记录重新读取，进入冻结的写作要求和评价契约。不会改变已有稿件、运行、评分或正式交付的版本绑定。撤销只影响此后的新任务。若草稿引用的约定已变化，重新打开下一期入口核对。既有学习试写仍使用原任务的冻结条件，不读取后来添加的约定。

普通对话可以读取约定、保存普通经验反馈，但不能直接保存或撤销长期约定。目前各宿主没有统一的可信用户动作身份，不能把模型提供的会话 ID 当作隔离边界。请在报告页点「下期沿用」或「撤销」。

下一期草稿的勾选结果按消息保存在服务端，生成时先核对请求明确指定的往期版本 ID 和哈希，两者均与关联一致才带入跳过项；缺失或不一致会报错，不替请求指定报告系列。模型不需要转抄排除列表。尚在排队的下一条消息不会覆盖当前回合。发消息后约定卡保留，便于补充期间等信息；取消关联后下一条消息清除其绑定。若执行回合缺失必要会话绑定，明确报错，不静默重新启用跳过项。其他会话或终端的无关新报告不受这一关联影响；无会话标识且明确指向正在关联的同一往期版本时，要求补全关联以避免漏掉跳过项。会话关联用于状态传递，不是进程安全隔离。

相同关联已实际发送后，后续消息只附简短版本定位与跳过项，不再重复整份要求。主 Agent 可通过只读 next_report 动作重新读取可沿用约定；宿主切换后也可使用此入口，不依赖隐藏提示词随历史迁移。首次、关联变化和未实际发送的情形仍携带完整约定。

写作约定是用户对写法的要求，不是来源证据，也不扩大联网、工具或费用权限。数字纠错通过本稿编辑与核对处理；用户更正不自动等于事实核验通过。复杂方法改进仍使用现有反馈与学习流程，调用模型前沿用现有授权及预算规则。

报告上会保留最近一次相关方法验证的状态，包括失败、未见足够改善或采用；可以查看依据与详情。轮数和自动学习放在「改进方法与运行详情」里。没有比较记录时不会写成「验证通过」或「已采用」。

本轮验证覆盖本地保存、刷新恢复、范围隔离、冻结、撤销、下一期排除和报告内结果展示。未新增真实模型调用；写作约定已进入输入不等于模型一定遵守，也不代表报告质量已提升。
