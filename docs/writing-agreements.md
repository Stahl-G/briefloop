# 写作约定与报告反馈

报告页右侧使用同一个输入框。点「发送」与 BriefLoop 讨论或修改本稿；明确希望以后沿用的写法，点「下期沿用」直接保存。保存约定不启动模型学习任务，也不需要等待试写比较。

默认只适用于这份报告及通过「开始下一期」关联的后续报告；可以主动选择「本工作区所有新报告」。系统不根据标题相似猜测报告系列。已保存的约定可以展开查看并撤销；下一期草稿也可以取消勾选某条，只跳过本期。

约定在新任务创建时从本地记录重新读取，进入冻结的写作要求和评价契约。不会改变已有稿件、运行、评分或正式交付的版本绑定。撤销只影响此后的新任务。若草稿引用的约定已变化，重新打开下一期入口核对。既有学习试写仍使用原任务的冻结条件，不读取后来添加的约定。

普通对话的 workspace-action 也支持读取、保存和撤销约定。保存需要当前用户消息中逐字出现的原话；后台报告角色不能把材料或自己的推断自动记为用户要求。是否属于明确长期意图、针对哪份报告，仍需主 Agent 正确理解；这不等于已验证所有宿主的实际调用行为。

写作约定是用户对写法的要求，不是来源证据，也不扩大联网、工具或费用权限。数字纠错通过本稿编辑与核对处理；用户更正不自动等于事实核验通过。复杂方法改进仍使用现有反馈与学习流程，调用模型前沿用现有授权及预算规则。

报告上会保留最近一次相关方法验证的状态，包括失败、未见足够改善或采用；可以查看依据与详情。轮数和自动学习放在「改进方法与运行详情」里。没有比较记录时不会写成「验证通过」或「已采用」。

本轮验证覆盖本地保存、刷新恢复、范围隔离、冻结、撤销、下一期排除和报告内结果展示。未新增真实模型调用；写作约定已进入输入不等于模型一定遵守，也不代表报告质量已提升。
