# 报告编辑与用户模板

BriefLoop 将报告内容保存为结构化富文档。网页可直接修改文字、强调、颜色、对齐、简单表格、图片与引用；Markdown 用于旧稿兼容和可选导入、导出。用户修改会产生新版本，原稿保留。

## 通用模板与我的模板

在“材料与需求”选择通用模板，或上传 DOCX 创建“我的模板”。BriefLoop 一次性识别章节、职责与本期可替换字段，程序准备模板底稿；后续选择已准备的模板即可复用。

工作区首次打开即自动注册内置版式矩阵：8 类文体（通用报告、商务报告、学术论文、政府公文、上市公司年报、合同、会议纪要、券商研报）× 5 套主题（极简蓝/商务蓝/学术黑/政务蓝红/创意橙），共 36 套——政府公文按 GB/T 9704 固定红头、仿宋与黑体标题，不随主题变化，只出正典一格。文体决定结构与封面（如公文红头、合同甲乙方表、研报评级卡），主题决定主色与字体字号。模板页为画廊布局：每类文体一张卡片（图标、适用说明、配色点），先点卡片选文体、再点配色点选主题，底部「已选」栏确认后点「使用该模板」即设为新建报告的默认版式并跳转新建表单；设置页模板下拉按文体分组。内置模板走与上传模板相同的准备管线，不调用模型，随包分发。

当前模板准备支持单节 DOCX 报告。遇到无法支持的版式会显示具体错误并保留原件，可调整主模板后重新导入；不会自动套用其他模板。当前不提供网页 Word 分页预览。

主章节和顺序默认沿用模板。页面可调整章节标题和必写/选用/人工填写职责；用户也可明确要求BriefLoop 增删或重排章节。人工填写小节在所属主章节内保留“待填充”。模板版本固定到本轮报告，修改默认模板不改变历史报告。

## 企业内部报告

选择“企业内部报告”写作方式后，正文直接组织本期变化、对组织的影响及有依据的行动。日期、单位和关键条件写在相应事实中，详细核查与待补信息放在独立面板。

初稿先显示。启用“评价后自动修订一次并复核”时，BriefLoop 根据独立评价安排一次修订，剩余问题保留供用户处理。用户已经编辑的版本不会被针对旧稿的自动修订覆盖。

## 生成 Word

修改保存后，按“生成 Word”。文件任务按阶段显示进度，完成后提供下载，用本机 Word/WPS 查看最终分页。普通制作由本地脚本完成，不需要另起模型会话。

按下按钮时固定正文、模板和图表资源版本。生成期间可继续编辑；新修改不影响正在制作的文件。需要新版 Word 时再次按按钮，不随每次编辑自动生成。

Word 保留所选模板的版式和支持的局部格式。正文长度改变时重新分页。网页用于编辑内容和基本样式，最终分页由 Word/WPS 显示。

行业定期报告与内置研报版式的 Word 输出自带目录页：标题自动写入书签，目录域在打开文档时由 Word/WPS 更新生成；正文层级中断不会阻断导出，但会在检查结果中显示。

## 图表和修订导入

表格支持内容编辑、增删行列、合并/拆分单元格及基本颜色。图表可以在网页替换、调整尺寸和图注；更复杂的改图要求交给 BriefLoop，它会核对关联数据、调用绘图脚本并登记新图表。

通过“导入 Word 修订”选择修改过的 DOCX，导入到当前报告版本。原件保留，可靠对齐后产生新版本和反馈；章节或不支持的对象无法可靠对齐时，先保留原件和提取结果，用户可请 BriefLoop 协助。原生 Office 图表、嵌套表格等复杂对象先在原件上核对，无法对齐时保留原件与提取结果。

## 企业背景知识库

企业内部周报开始前，BriefLoop 可以提议维护企业背景知识库。用户选择启用后，每次运行可在当次权限和预算内扫描公开 PR、年报、季报等，保存有来源、日期和历史的更新。

用户提交的资料与已保存记录冲突时，在企业背景面板确认采用新资料或保留原记录。企业事实与 WikiSkill 的方法经验分开保存。

## 开发接口

- `POST /api/save` 接收 `base_version` 与 `editor_document`；旧 Markdown 保存仍可兼容。新报告以富文档内容为准，纯格式变化也产生版本。
- `POST /api/template-import` 接收 DOCX 的 `name`、base64 `data`，可提供更新来源 `parent_id`。
- `POST /api/export` 接收 `version_id`，返回 `export_docx` 文件任务；完成后使用任务结果里的 `download_url`。
- `GET /api/research-notes?version=...` 返回该版本的核查、待补与来源信息。
- `POST /api/import-revision` 接收 `base_version`、DOCX `name/data`；无法对齐时返回 `needs_alignment`，保留来源 ID。
- `GET /api/company-context` 查看企业背景和待确认记录。

Agent 可用 `briefloop tool --workspace ... normalize-document --file document.json` 检查内容结构，并通过现有 `workspace-action` 读取/修改报告、准备模板、导出 Word 及维护企业背景。

### Opencode 自定义模型

在设置中点击“添加 Provider / 自定义模型”，填写 Provider ID、API Base URL、模型 ID 和 API Key，保存后可直接选用。首版支持 OpenAI 兼容的 Chat Completions 接口。使用 Opencode 原生全局配置和凭据接口，配置供本机工作区共用；同名 Provider 保存会更新其接口，新增模型保留已登记的其他模型。Key 留空沿用现有凭据；填写会更新同名 Provider 的本机 Key。密钥不会写入 BriefLoop 的任务、报告或配置返回值。保存配置不会调用模型，实际连通性在用户发起任务时验证。

带目录的报告在导出时保存可点击的标题列表，未刷新域的阅读器也能显示并跳转；精确页码需在 Word/WPS 中更新目录域，是否自动更新取决于阅读器设置。换版式只生成新的导出文件，已保存正文、版本和报告设置保持不变。
