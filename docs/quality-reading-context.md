# 评价所见稿件与研究收尾

普通 Evaluator 同时获得保存的稿件和由产品渲染器生成的 `reader-preview.md`。后者将内部引用标记转换成读者引用，避免把存储协议误判成报告中暴露的错误文本。Reviewer 的阅读预览和 `reading-context.json` 进入原有只读任务包的文件指纹，仍按实际稿件、原件和任务历史审阅。

阅读上下文只说明保存记录是否存在及其数量，不认证其语义正确。缺少数字、时间或引文机器绑定，不等于事实已证实错误；已存在的绑定也不能代替来源核对。评价发现需锚定真正有问题的原句，区分“未取得证据”与“反证不存在”，避免摘要和正文同一原因重复计为独立错误。

研究轮结束时，收尾摘要与 handoff 中的 covered、follow_ups、open_questions 冻结到该轮 outcome，并经现有 retrieval_notes 传给后续写作、修订或研究。历史收尾不受后续临时 handoff 文件修改影响。研究 Agent 在既有轮次、网络许可和预算内判断是否需要针对关键二手材料和重要遗漏补查；不会自动扩轮、自动认证缺口已闭合，Reviewer 仍不负责联网补搜。

普通 Word/HTML/Markdown 来源列表隐藏网页来源的纯抓取行号（例如 `lines 12–17`）。真实保存的引文、审计原件、本地文件行号及有意义的页码/章节/表格定位保留。该规则不改写作者正文，也不猜测缺少来源类型信息的定位。

Native 主 Agent 的 `write_report` 在 `quality_v1` 下先检查已冻结计划：不能有 active 轮次，最新实际开启轮次必须已 closed 且保存 outcome，随后才启动 Analyst。只有 `plan.json` / `research.json` 文件不代表研究已经收轮。被拒时返回现有 `save_research_handoff`、`finish_research_round` 的下一步；不自动补搜、开轮或增加预算。

open/partial 缺口、预算耗尽、深度计划中尚未开启的 pending 轮次均不阻止明确收轮后写稿。旧 closed outcome 没有新增 closeout 字段或 summary 为空，仍按原收轮记录兼容；legacy 协议沿用旧路径。这个检查证明主 Agent 留下了收尾记录，不证明候选覆盖完整、二手消息已核实或报告事实正确。

本次行为检查覆盖实际阅读输入、任务包篡改拒绝、旧软篇幅快照兼容、研究收尾冻结与来源导出。它们证明信息传递和版本绑定，不证明模型已降低误报、完整补查或提升阅读质量；相关真实模型与人工验收仍需单独记录。已发布版本及旧实验不作追溯修改。

## 保存时的缺口与本次核查的研究状态

评分、修订和新建的审阅包现在同时保留两组记录：`research_context.saved_report` 是被处理稿件保存时的 gaps/gap_records；`current_research` 是该任务包生成时，应用依据显式 gap_updates 和可定位依据投影出的当前 open/partial/resolved 记录。两者绑定原稿 ID/hash，并保留当前研究状态的内容哈希。审阅包另存 `research-context.json`，纳入已有文件指纹校验。

此改动修复评分只看到旧“未取得”提示、没有取得最新解决记录的问题。它不覆盖旧稿 gaps，不将后来材料伪装为写稿时已知，也不自动更改评分、审阅或正式交付状态。resolved 仍然是研究 Agent 的带依据判断，Evaluator/Reviewer 要回读来源判断支持范围；没有显式更新、来源仅仅入库或当前记录为空，都不能证明缺口已解决。依据失效会重新显示 open。

修订继续检查摘要、正文、表格和影响段的同因残留，保留主体、期间、计划/生效、公测/正式可用等条件。新上下文只提供核查信息，不增加评分维度、机械语义规则、联网权限或修订轮次。旧冻结包保持原样。

验证是隔离合成材料上的真实任务包生成、版本不变及定位校验；尚未新增真实模型对照，不能宣称语义错误检出率或实际报告质量改善，#816 保持开放。
