# 深度研究与事实核查

0.21.0 的研究选项与 Word 版式相互独立。新建报告时先确定用途、读者和材料，再选择研究深度；选择模板不会自动开启联网或事实核查。

## 研究深度

| 档位 | 研究组织 | 页面带入的默认预算：搜索请求 / 候选 URL / 全文来源 |
| --- | --- | --- |
| 快速 | 单轮检索 | 6 / 30 / 12 |
| 标准 | 最多三轮，按缺口补查 | 30 / 150 / 60 |
| 深度研究 | 预排四轮，逐轮交接发现与追问 | 80 / 400 / 150 |

这些数字是起始设置，用户可在研究预算中修改。任务开始后冻结实际档位、预算、宿主与搜索源；恢复已有任务继续使用原配置。多轮不保证一定能找到更多有效材料；达到预算上限会留下当前结果与缺口，不自动加额。

在「设置 → 运行与搜索」选择宿主原生搜索、Tavily 或 DuckDuckGo。DuckDuckGo 无需填写搜索 API Key，但模型调用仍由所选宿主和账号计费，搜索服务也可能限流或失败。Tavily 使用其配置的凭据；原生搜索能否联网由宿主能力和权限决定。受控搜索记录请求与来源用量，原生宿主搜索不宣称精确计量全部搜索次数。

每轮交接保留研究发现、来源 ID、定位和下一轮问题。系统检查定位格式及来源归属；这不等于证明原文支持该结论。正文、核查意见和内部研究记录各有位置。

## 生成后的独立事实核查

在新建报告中勾选「生成后独立核查公开主张」。默认关闭；未允许联网时不能启用。任务保存实际开关，之后改工作区设置不会追溯改变旧任务。

执行顺序为：保存可编辑草稿 → 独立核查公开主张 → 独立审阅 → 按设置自动修订一次并复核。核查需要正文中已经登记并绑定的主张；没有可核查主张、研究阶段仍未收束或无法接纳预算时，会记录原因，不能显示为已完成核查。

核查员在独立会话中选择重要公开主张，进行中性和反证检索，登记来源原件与证据位置，并提出以下候选：

- **范围内支持**：当前证据支持该主体、期间、单位和条件下的表述。
- **矛盾**：找到与该表述不一致的证据，仍需审阅核对口径。
- **证据不足**：现有证据无法支撑判断。
- **未知**：尚无法明确判断。

这些是核查候选。Reviewer 继续在只读环境中核对稿件、原件和候选；不会因为有引用或一次搜索就自动打上「事实已证明」。执行完成、预算用完、取消和失败是任务状态，与事实判断分开显示。

核查优先使用本次任务授权预算内的份额，不自动扩大共享上限。若额度不足，可以在核查面板显式追加预算；这可能产生新的模型和搜索消耗。传输失败保留失败任务和已有稿件，可按页面入口恢复，不能把未提交结果写成成功。

核查结果与稿件版本、正文块、引用及搜索配置绑定。改稿后旧结果保留历史身份，不能直接当成新稿的核查结论。核查记录和必要限制在质量面板查看，正文只保留影响判断的具体条件。

## 定时报告与外部 Agent

[定时报告](定时报告.md)保存计划所用需求，包含研究档位与核查选择；保存时确定核查开关，后续更改工作区默认值不会自动开启既有计划的核查。每次触发生成独立任务并冻结本次配置。首页可修改预设或自定义频率、暂停或停止本次任务。程序未运行时不会执行，也不会补跑停机期间的全部计划。

外部 Agent 可经 [external CLI](WorkBuddy外部入口.md) 的 `submit` 请求，在 `requirements` 中传入 `research_tier`（`quick`、`standard`、`deep`）和 `fact_check`（布尔值）；联网核查还要求 `allow_web: true`。仍使用既有 request_id 幂等、任务查询、版本修改和导出接口。

WikiSkill 沿用已核实的修订和反馈形成经验；核查候选本身不直接变成本期事实或已证明的学习收益。
