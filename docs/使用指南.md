# BriefLoop 0.17.1 使用指南

## 对话、材料和工作区

工作区是一个本地目录，保存数据库、来源、稿件、对话和 Wiki。空目录也能使用：先描述目标，或在“材料与需求”设置正式报告要求。打开目录不意味着模型已经开始工作。

侧栏可以切换最近工作区、打开目录或新建目录。切换不会停止其他工作区中的任务。打开尚未运行的已有工作区时，旧排队任务保留供手动恢复，自动学习暂不启动；需要时在设置中明确开启。

对话输入区支持文件附件、联网、模型、推理档位、provider 和权限。空闲时发送开始一轮；运行中可以排队，或选择“立即补充”。“已送达”表示执行端接受输入，不等于已经执行要求。页面只展示公开消息和工具活动，不展示私有推理。

## 整理对话

每条对话旁的“⋯”提供归档或移到回收站。列表可以切换“最近对话／已归档／回收站”，后两者可阅读并恢复。恢复不会重发旧消息，也不会自动收费。

“归档已结束”批量整理已有消息且当前空闲的对话。运行中、正在停止、有排队消息或等待回答的问题时，先完成或停止任务再整理；清理操作不会隐式取消任务。

这些操作只管理对话，不删除报告、来源、Wiki 或任务记录。明确恢复一个任务时，如果旧执行会话已归档或删除，会创建新的恢复会话，并保留旧关联。

## 模型与权限

主链和 Evaluator、Wiki Maintainer、Skill Proposer 可以分别配置模型。常用模型只是输入建议，自定义 ID 原样交给所选宿主。Codex 的 provider 填写本机 Codex 中已经配置的名称，留空沿用本机配置；其它宿主使用它自己的账号与模型配置（Opencode 可另外在“API 提供商”登记协议、Base URL、Key 和模型）。“模型默认”不额外传推理档位。

执行宿主可在设置页切换，已排队或已开始的任务冻结原宿主。输入区只显示当前宿主真正支持的控件：权限档位来自宿主声明的能力，只有一个档位时不显示该下拉；“立即补充”只在支持运行中追加的宿主出现；不支持读图的宿主会在附图时直接提示。切换宿主会清空不再适用的角色模型，留空即继承主链模型。

新任务会保存当时的配置。修改设置不会改变正在执行的任务。切换 provider 会在下一轮建立新的执行上下文，历史消息仍可查看；不会擅自跨 provider 转发全部旧历史。底层不支持某模型或工具时会报告错误，不自动换成别的模型。

只读模式用于查看与讨论，工作区读写用于保存产物。修改权限在后续轮次生效，向当前轮补充消息不改变它。正常生成和学习任务需要写入当前工作区。

## Tavily 与来源

在联网开关下选择 Tavily 并保存 Key，也可从设置管理。密钥优先读取环境变量 `TAVILY_API_KEY`，否则读取 `~/.config/briefloop/tavily.key`，本地文件权限为 0600。Key 不进入工作区、聊天、Wiki、技能或 API 返回值。移除本机文件不会删除环境变量。

保存 Key 不调用 Tavily。正式检索会消耗相应账户额度。开启 Tavily 的研究任务给检索 Scout 提供内置技能，使用 Search 发现页面、使用受控来源工具保存材料，必要时再用 Extract。无需安装第二个 CLI 或技能仓库。

来源面板区分网站原始响应和 Tavily 提供方提取正文。两者都可保留供查看，但提供方文本不等于网站原始字节。搜索摘要只能作为线索；原件、提取文本、抓取时间和模型的判断也不能互相替代。

## 预算和覆盖

周报预设为 12 次搜索尝试／60 个候选 URL／18 个全文来源 URL；月报为 30／200／45。三个数可修改，0 表示不提供该类新增额度。它们随本次报告保存，由所有 Scout 共享。

工具调用前以数据库事务预留额度，失败的搜索仍计次。并发结果超过候选额度时，未纳入的 URL 会明确列出，完整提供方响应保留在本地 discovery 记录中。已成功取得的同轮 URL 可复用；跨轮不默认用旧快照。同一 URL 的直接失败、Extract 回退和重试只占一个全文 URL，但可能有多个 HTTP 尝试。

Tavily Search 请求与候选可精确计量；宿主自带搜索（Codex、Opencode、各 CLI 的联网工具）的这两项不能精确计量。受控 add-url／Extract 的全文 URL 仍计量。界面会显示当前报告的上限、已用和剩余，不把获取数量叫作已核验数量。

预算是成本边界，不是质量证明。达到额度后使用已有证据并报告重要缺口，不自动继续深挖或加额。行业定期报告共用同一套预算；本版不提供托管式 Deep Research 服务，研究深度取决于所选宿主的能力与本次预算。

## 稿件、评分和学习

字数预设分别为目标／上限 800／1000、1500／2000、2000／2500。可自定义数字。正文保留必要的行内引用，长摘录和定位应留在来源记录。计数工具与页面共用规则；模型被要求发布前检查，页面会明确显示超限。

原稿和修订各自保存，评分绑定具体稿件内容。旧评分不自动套用到改写后的稿件。Evaluator 的四维分数与具体问题可供参考，用户可以不同意；低分不会隐藏正文。

评论和人工改稿都可成为反馈。开启自动学习后，服务在编辑静默约 30 秒后合并一批；也可以明确手动启动。Wiki Maintainer 整理经验，Skill Proposer 提出技能，再由实际产物比较决定是否采用。Wiki 保留经验，不作为本期事实来源。

K 控制一次反馈学习最多尝试多少轮；轮数越多消耗的 Token 和耗时越多，候选越好会提前结束。候选已产生但验证暂停时仍可查看；继续验证会调用模型。若模型设置改变，恢复会创建新的执行。

## 运行与恢复

关闭网页不停止服务。运行中可以停止；完成文件和失败信息保留，任务可以明确恢复。不要在模型工作时直接杀服务。代码升级后应在任务结束时重启，以使前后端一起更新。

服务日志位于工作区 `server.log`，任务输出位于 `jobs/`。请备份整个工作区，不只复制数据库。诊断命令：

```sh
.venv/bin/briefloop --version
.venv/bin/briefloop status --workspace /path/to/workspace
.venv/bin/briefloop doctor --workspace /path/to/workspace
```
