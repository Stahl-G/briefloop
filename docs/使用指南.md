# BriefLoop 使用指南

桌面安装、环境准备和版本更新见 [桌面安装与更新](桌面安装与更新.md)；WebUI 启动见 [README](../README.md)。

## 对话、材料和工作区

工作区是一个本地目录，保存数据库、来源、稿件、对话和 Wiki。空目录也能使用：先描述目标，或在“材料与需求”设置正式报告要求。打开目录不意味着模型已经开始工作。

侧栏可以切换最近工作区、打开目录或新建目录。WebUI 切换不停止其他独立后台的任务；桌面 App 一次管理一个活动工作区，切换前保存并停止当前后台，运行中的任务会先请你确认停止。目标打开失败时尝试恢复原工作区，中断任务不会自动重发。打开尚未运行的已有工作区时，旧排队任务保留供手动恢复，自动学习暂不启动；需要时在设置中明确开启。

对话输入区支持文件附件、联网、模型、推理档位、provider 和权限。空闲时发送开始一轮；运行中可以排队，或选择“立即补充”。“已送达”表示执行端接受输入，不等于已经执行要求。页面展示公开消息、工具活动和宿主返回的思考内容（折叠的“思考”条，仅本地查看）；思考内容不进入报告、通知或审计包。

## 整理对话

每条对话旁的“⋯”提供归档或移到回收站。列表可以切换“最近对话／已归档／回收站”，后两者可阅读并恢复。恢复不会重发旧消息，也不会自动收费。

“归档已结束”批量整理已有消息且当前空闲的对话。运行中、正在停止、有排队消息或等待回答的问题时，先完成或停止任务再整理；清理操作不会隐式取消任务。

这些操作只管理对话，不删除报告、来源、Wiki 或任务记录。明确恢复一个任务时，如果旧执行会话已归档或删除，会创建新的恢复会话，并保留旧关联。

## 模型与权限

主链和 Evaluator、Wiki Maintainer、Skill Proposer 可以分别配置模型。常用模型只是输入建议，自定义 ID 原样交给所选宿主。Codex 的 provider 填写本机 Codex 中已经配置的名称，留空沿用本机配置；其它宿主使用它自己的账号与模型配置（Opencode 可另外在“API 提供商”登记协议、Base URL、Key 和模型）。“模型默认”不额外传推理档位。

执行宿主可在设置页切换，已排队或已开始的任务冻结原宿主。输入区只显示当前宿主真正支持的控件：权限档位来自宿主声明的能力，只有一个档位时不显示该下拉；“立即补充”只在支持运行中追加的宿主出现；不支持读图的宿主会在附图时直接提示。切换宿主会清空不再适用的角色模型，留空即继承主链模型。

新任务会保存当时的配置。修改设置不会改变正在执行的任务。切换 provider 会在下一轮建立新的执行上下文，历史消息仍可查看；不会擅自跨 provider 转发全部旧历史。底层不支持某模型或工具时会报告错误，不自动换成别的模型。

只读模式用于查看与讨论，工作区读写用于保存产物。修改权限在后续轮次生效，向当前轮补充消息不改变它。正常生成和学习任务需要写入当前工作区。

Antigravity 支持在对话中附图，由宿主的 `view_file` 工具读取本地图片；图片路径仍需符合宿主文件权限。权限入口提供默认、全机访问、Turbo 和自定义四种预设，保留宿主已有的终端沙箱设置。Turbo 也保留已有的逐工具询问或拒绝规则。自定义规则保存到本机 Antigravity 配置，会影响使用该配置的其他会话。

Antigravity 的无界面执行无法弹出逐项授权窗口。工具被拒绝时，对话显示工具名称和错误详情；用户可明确调整对应规则后重新发送。复制消息或来源链接时，浏览器禁止剪贴板 API 后尝试本地复制回退，失败会保留提示。

## 搜索渠道与来源

新工作区默认采用 Tavily 优先并允许宿主自带搜索补充，无需二选一；已有任务保持冻结策略。博查和智谱搜索需要用户主动启用。智谱搜索 Key 在同页保存，也可使用 `ZHIPU_SEARCH_API_KEY`；可选择智谱基础版、智谱高阶版、搜狗或夸克引擎。保存 Key 不会自动执行搜索。


在「设置 → 运行与搜索」选择一个首选，再勾选允许的补充渠道。首选可选宿主、Tavily、DuckDuckGo、博查或智谱搜索。补充策略有三种：

- **检查跨市场覆盖并补缺**：即使首选已有结果，也安排少量互补查询检查重要遗漏；由 Agent 根据内容需要决定，不强制耗尽额度。
- **仅在发现缺口时补查**：缺原文、关键主体遗漏、冲突或渠道失败时使用补充渠道。
- **只用首选**：不启用其他搜索渠道。

可填写关注市场与语言。公众号、小红书尚无专门接入，不展示平台开关。博查提供中国市场网页搜索；平台链接是否能搜到、正文是否可读需逐条检验，不能把搜索摘要当全文。无法读取时可导入你有权提供的正文、截图或文件。

点击「保存搜索策略」后，新报告采用该选择；排队、运行、恢复和事实核查沿用本轮快照，不跟随之后的工作区设置变化。定时报告若保存了显式搜索策略则沿用该策略，否则在每期入队时冻结工作区设置。

Tavily、博查和智谱搜索分别需要 Key。优先读取 `TAVILY_API_KEY` / `BOCHA_API_KEY` / `ZHIPU_SEARCH_API_KEY`，否则读取 `~/.config/briefloop/tavily.key` / `bocha.key` / `zhipu.key`。本机文件权限为 0600，供本机工作区使用；Key 不进入工作区、聊天、Wiki 或接口返回值。移除文件不删除环境变量。保存 Key 不调用搜索，实际查询可能消耗对应账户额度。

研究任务使用内置多渠道技能和统一 `web-search --provider tavily|bocha|duckduckgo` 工具，记录 primary、coverage_probe、gap_repair 用途与原因。没有 Key 或请求失败时，保留错误，只能使用本轮已允许的替代渠道。没有额外账户时可以只用免搜索密钥的 DuckDuckGo 或已有宿主能力，模型费用仍由宿主账号承担。

「研究预算 → 查看搜索记录」展示已保存的受控查询、渠道、耗时和错误。「数据源」可按发现渠道筛选；未记录渠道的材料明确显示未记录，不猜测来源。搜索发现渠道与网站原始响应、Tavily 提取正文分开：提供方摘要或提取文本不等于网站原始字节，更不代表事实已核实。

宿主搜索开关传给实际执行层。能否调用取决于宿主提供的工具及原生权限；不能精确观察的搜索次数和底层索引显示未知，不并入受控 API 次数。该开关不是全机网络隔离，Reviewer 仍按独立只读权限运行。

## 预算和覆盖

周报预设为 30 次搜索尝试／150 个候选 URL／60 个全文来源 URL；月报为 80／400／150。三个数可修改，0 表示不提供该类新增额度。它们随本次报告保存，由所有 Scout 共享。

工具调用前以数据库事务预留额度，失败的搜索仍计次。并发结果超过候选额度时，未纳入的 URL 会明确列出，完整提供方响应保留在本地 discovery 记录中。已成功取得的同轮 URL 可复用；跨轮不默认用旧快照。同一 URL 的直接失败、Extract 回退和重试只占一个全文 URL，但可能有多个 HTTP 尝试。

Tavily、博查、智谱搜索和 DuckDuckGo 的受控搜索请求与候选共用硬预算并可精确计量；宿主自带搜索（Codex、Opencode、各 CLI 的联网工具）的这两项不能精确计量。受控 add-url／Extract 的全文 URL 仍计量。界面会显示当前报告的上限、已用和剩余，不把获取数量叫作已核验数量。

预算是成本边界，不是质量证明。达到额度后使用已有证据并报告重要缺口，不自动继续深挖或加额。行业定期报告共用同一套预算；本版不提供托管式 Deep Research 服务，研究深度取决于所选宿主的能力与本次预算。

## 稿件、评分和学习

字数预设分别为目标／上限 350／500（速览）、800／1000、1500／2000、2000／2500。可自定义数字。正文保留必要的行内引用，长摘录和定位应留在来源记录。计数工具与页面共用规则；模型被要求发布前检查，页面会明确显示超限。

原稿和修订各自保存，评分绑定具体稿件内容。旧评分不自动套用到改写后的稿件。Evaluator 的四维分数与具体问题可供参考，用户可以不同意；低分不会隐藏正文。

评论和人工改稿都可成为反馈。开启自动学习后，服务在编辑静默约 30 秒后合并一批；也可以明确手动启动。Wiki Maintainer 整理经验，Skill Proposer 提出技能，再由实际产物比较决定是否采用。Wiki 保留经验，不作为本期事实来源。

K 控制一次反馈学习最多尝试多少轮；轮数越多消耗的 Token 和耗时越多，候选越好会提前结束。候选已产生但验证暂停时仍可查看；继续验证会调用模型。恢复会沿用该任务原来的模型与后端；要改用当前设置，请新建任务。

## 执行时限与错误

在设置中选择本次执行时限，0 分钟表示“不限时”。该选项取消整轮执行期限，不关闭手动停止，也不隐藏宿主返回的失败。提供商返回 429、503 或额度不足时，对话显示错误；宿主实际重试时显示重试状态。纠正账号、模型或服务配置后，可以按界面提示重新发送或恢复任务。

“我的报告”的任务卡显示当前阶段、累计等待／运行时间、最近活动记录和已保存材料；展开“研究过程”可查看已记录的研究轮次、子任务、证据对照与修订过程。受控搜索显示成功与失败请求数；宿主原生搜索没有可比计数时不显示数字。材料已保存不表示已经核验，初稿保存后即可打开，评分或修订可以继续进行。

报告任务等待工具权限时，进度中提供入口打开其绑定的对话，在那里处理宿主的实际授权请求。

## 运行与恢复

关闭网页不停止服务。运行中可以停止；完成文件和失败信息保留，任务可以明确恢复。不要在模型工作时直接杀服务。代码升级后应在任务结束时重启，以使前后端一起更新。

服务日志位于工作区 `server.log`，任务输出位于 `jobs/`。请备份整个工作区，不只复制数据库。诊断命令：

```sh
.venv/bin/briefloop --version
.venv/bin/briefloop status --workspace /path/to/workspace
.venv/bin/briefloop doctor --workspace /path/to/workspace
```

### 上传大小

网页上传原件、Word 模板或 Word 修订时，单文件上限为 18 MiB；每个请求含 Base64 与 JSON 后须小于 25 MiB。多选文件逐个上传，先检查整批文件的大小，超限时显示文件名和本批总量，不先上传一部分。请压缩或拆分过大的文件后重试。来源文件是否可由模型读取，还取决于解析结果和所选宿主能力。
