# BriefLoop 0.30.0

本页说明本轮变更；渠道发布与安装状态以正式发行清单为准，开发分支上的文档不表示已经发布。

## 本轮改进

标准生成中的「按目标补证（试用）」现在围绕本轮关键问题保存研究判断、原文定位、未答部分和收束理由。在任务的研究过程中直接查看，点击来源回读保存的正文。材料不足时仍可交出明确受限的工作稿；“有依据”不等于已经独立核查。

主 Agent 可以直接研究集中问题，也可以按需要委派独立支线。不再仅因为初始来源为空就强制创建 Scout。任务的预算、允许渠道、停止和恢复以及既有独立评价、修订和正式交付规则继续有效。

本轮修复三个会妨碍检索或读取的问题：DuckDuckGo 单次返回过多候选挤占其他查询额度；把特定搜索渠道的查询长度限制套用到其他渠道；gzip 压缩网页和部分访问验证页被错误当作可用正文。压缩网页保留原始响应和校验值，损坏或解压过大时显示失败。

本版同时包含0.29未公开发行阶段已合并的新建报告、下一期约定、经验反馈和图文包导入等改进；详细变化见[变更记录](../CHANGELOG.md)。

## 默认设置与边界

默认仍为分轮研究。公开联网对照结果随题目变化，小样本没有证明目标驱动稳定更快或质量更高，因此不将试用模式自动改成默认。研究状态帮助解释过程，不能替代阅读实际稿件和证据。

联网快速模式仍是一轮有限检索、初稿保存、补依据与评价，不能保证复杂报告的必答问题全部覆盖，也不使用标准流程的研究策略开关。本轮真实复测保留了检索失败及未运行样本，没有用补跑成功稿掩盖失败。详细使用说明见[按目标补证](目标驱动研究.md)。

原文读取成功也不保证内容完整：动态网站可能不返回所需表格，来源引用和时间、口径仍需核对。检索失败时不会凭搜索摘要生成没有原文支撑的报告。

## 发行一致性

Mac、Windows、Python/CLI 必须复用同一冻结提交构建的一份后端 wheel；各平台独立完成实际启动、保存、导出和升级核验，再统一公开。发布后沿正常升级流程替换日常安装，不把开发候选安装成多个正式 App。
