# Codex 会话历史隔离

BriefLoop 的 Codex app-server 使用独立、持久化的 `CODEX_HOME`。默认位置是用户目录下的 `.config/briefloop/codex-homes/<原 Codex 目录摘要>`，不在报告工作区内。SQLite 状态和日志也指向该目录，避免原配置里的 `sqlite_home` 将新会话写回个人历史。

这是历史存储隔离，不是权限沙箱：原有审批策略、文件访问和联网边界不变。没有使用 ephemeral 会话，也没有关闭恢复记录。

## 登录与配置

文件登录模式通过符号链接沿用原 Codex 的 `auth.json`；不复制密钥到工作区，也不将凭据写进日志。用户配置、独立配置档及常用规则/技能目录也使用链接。目录内只复制明确需要恢复的旧会话文件，不复制整套个人历史、记忆或数据库。

密钥链、auto、ephemeral 登录不能据此假设可跨 home 复用。无法建立文件链接的系统（例如未启用符号链接权限的 Windows）也不会静默回到共享历史。可用 `BRIEFLOOP_CODEX_HOME` 指向一份**已经独立配置和登录**的 Codex home；此时 BriefLoop 不覆盖或链接其中的配置/凭据。先使用该目录作为 `CODEX_HOME` 完成正常 `codex login`，再启动 BriefLoop。原个人登录不退出、不覆盖。

具有额外相对路径的自定义配置必须在独立目录中验证，或改为明确的绝对路径。自定义目录应位于报告工作区之外。独立目录不能与原 Codex home 相同或位于其内部。

## 原有会话

继续旧对话时，仅按 BriefLoop 保存的 thread ID 定位旧 rollout，复制到独立目录后交给 Codex 恢复。原件保留；已有独立副本不会被覆盖。检测到复制期间原文件仍有写入会中止迁移，而不是带着已知不完整记录继续。请勿在两个客户端同时推进同一个旧会话。

本改动不会批量删除或归档个人列表中的旧条目。它们需要依据 BriefLoop 的确切会话绑定另行整理，不能按标题相似就删除。新产生的线程不再写入原目录。

## 验证范围

2026-10-09 在 macOS、Codex CLI 0.159.2 上使用本地合成 Responses SSE 服务验证：新私有线程不出现在原 home 的 thread/list 中；关闭 app-server 后可重新恢复并继续；已绑定旧线程可导入继续，原 home 的文件保留。响应由本机模拟服务返回，没有调用真实模型或消耗额度。

另外验证了本机现有 ChatGPT 文件登录在独立目录中仍被 `account/read` 识别，仅记录认证状态，不记录凭据。使用临时目录和虚构 API Key 验证 CLI 保存登录时保持 auth.json 链接；没有改动真实登录。

实际浏览器验收使用独立合成工作区、现有 Codex 文件登录及宿主默认模型：通过页面选择模型、发送消息，停止并重启预览服务后重新打开同一对话，第二轮正确返回首轮测试代号。两轮均完成且 thread ID 不变；专用目录有该线程，个人 sessions/archived_sessions 与 SQLite 中没有，官方近期线程列表也未列出。Codex 原生窗口不允许电脑操作工具访问，因此未声称完成其侧栏的视觉验收。

Windows 实机、密钥链独立登录、真实 OAuth 过期刷新以及发行 App 更新路径尚未验收；Windows 单元 CI 不等于完整登录验收。非文件登录或缺少符号链接权限的安装需先按上述独立 home 流程配置；升级前必须说明这一兼容性要求。代码合并不代表正式安装已升级或所有平台已就绪，剩余验收继续由 #906 跟踪。
