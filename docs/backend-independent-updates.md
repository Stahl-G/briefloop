# 后端独立更新（生产更新源尚未启用）

桌面壳保持签名和公证完整。更新包放在应用数据目录，以签名发布清单授权，复用现有环境准备、工作区服务和保存门禁。

首版仅接受同一依赖锁、桌面协议和数据库兼容代际的稳定后端版本。原生组件、依赖锁或存储代际改变时，提示整包升级。

发布清单用独立 Ed25519 密钥签署原始 UTF-8 负载，桌面壳固定公钥和 GitHub 发布来源。负载绑定版本、单调发布序号、到期时间、wheel 名称/大小/SHA-256、依赖锁与兼容范围。
私钥不入仓库；客户端拒绝未知签名、篡改、过期、版本或发布序号倒退。回退只允许本机已验证的上一环境，不降低所见最高发布序号。

下载与准备可以在后台完成，不停止当前任务。新组件复用已验证运行环境的锁定依赖，在独立目录准备；原环境指针不变。切换必须先保存并确认没有运行或排队任务；新环境先在临时工作区测试启动、保存和导出，再关闭原服务。
新服务启动成功后才确认活动后端，失败回到原服务，保留工作区及未完成任务。首版不执行破坏性数据库迁移，不通过恢复旧数据库实现回退。
重启时若发现未确认的切换，恢复上一个已确认后端；同一时间仅允许一次更新事务。

界面仍使用原来的检查更新入口。兼容时显示研究组件更新，不兼容则走完整 App 更新；不提供新的研究模式。
实际外部后端代码能否启动及其安全策略由目标平台验证；不将“不修改App”表述成免除所有软件签名、来源和执行权限要求。

验收至少覆盖：签名或内容篡改拒绝、准备失败不改当前环境、任务忙时不切换、切换启动失败恢复、进程中断恢复，以及真实工作区报告保存与导出。
正式启用前必须进行实际轮换和发布密钥保管核验。

## 发布与保管

生产更新源固定为本仓库 `releases/download/backend-stable/backend-update.json`。
签名清单引用的 wheel 放在对应 `v版本` 的 release，该 release 不标为 latest，避免影响旧桌面客户端的整包更新。
客户端只接收固定 GitHub 仓库的下载及其 HTTPS CDN 重定向。开发版可显式设置
`BRIEFLOOP_BACKEND_UPDATE_TEST_FEED` 为 `http://127.0.0.1:端口/清单`，正式打包 App 忽略该变量。

签发命令：

```sh
node desktop/electron/scripts/sign-backend-update.cjs \
  /path/to/frozen/backend /secure/path/publisher-key.pem briefloop-backend-2026 \
  1 2026-12-01T00:00:00Z '>=0.31.8 <0.32.0' /path/to/backend-update.json
```

只有签名私钥持有人可授权更新。私钥不进入App、Git、安装包或发布日志，生产启用前应备份到单独安全位置；
更换公钥需要整包签名发行。签发前需审查存储及API变化是否确实向后兼容，不能仅依赖清单声明。
准备阶段比较实际新建数据库DDL，检查临时工作区启动、记录保存及Word/Excel回读，仍不能代替所有历史数据迁移验证。

已在 Mac 开发版通过签名回环更新源下载真实0.31.6→0.31.7 wheel，完成原生按钮、忙任务阻止切换、保存与自动重开、
未确认启动恢复旧组件、再次切换后确认及报告恢复。修复了独立环境未复用依赖与欢迎页缺少环境状态通知的问题。
该机制尚未进入正式App，生产更新源未发布；仍需一次整包升级才能交付客户端能力。
独立安装的CLI按自己的安装渠道更新；现有自定义桌面CLI启动脚本不会自动跟随组件目录切换。
