# 升级到 0.18.0

0.18.0 统一了公开发布身份，并让 PyPI 安装自包含。

- Python 分发名由 `briefloop-local` 改为 **`briefloop`**；CLI 仍是 `briefloop`。
- `wikiskill`（BriefLoop 使用的补丁版）作为顶层模块内联在本发行版中，不再依赖 PyPI 上不存在的外部包。`pip install briefloop` 直接可用。
- 英文站与 README 曾停留在 0.15.x 旧定位；本版以后公开表面统一到当前产品。

先结束正在执行的任务，再更新代码并重新启动服务。浏览器不会热替换正在运行的后台版本。多运行时桥接需要 Node.js 20+；使用的 CLI 需自行安装并配置账号。

## 安装

从 PyPI（推荐）：

```sh
pip install briefloop
briefloop start --workspace /path/to/workspace
```

从源码：

```sh
git clone --branch v0.18.0 https://github.com/Stahl-G/briefloop.git
cd briefloop
./start.sh
```

源码包内不再需要单独安装 WikiSkill wheel；`start.sh` 会安装当前仓库。

模拟周报位于 [examples/internal-weekly-report](../examples/internal-weekly-report/README.md)，可从合成材料体验生成、改稿和 Word 导出。

## 0.17.0 架构升级说明

0.17.0 将之前的工作流工具改为基于 Codex CLI app-server 的本地交互工作台。旧提交与 v0.15.3 等发布标签仍保留；这不是旧工作区数据库的自动迁移。

建议先保留旧版本与旧目录，在新工作区使用 0.17.0，再按需要导入原始材料。不要把旧 ControlStore、配置或实验状态直接覆盖到新数据库；新界面与新预算机制按本版文档工作。

0.17.0 当时的状态（后续变化已在括号中注明）：

- 单仓库启动，不再要求用户另行 clone WikiSkill。
- CLI 为 `briefloop`，Python 包名当时为 `briefloop-local`（0.18.0 起为 `briefloop`）。
- 以 macOS 本地使用为已验证路径，服务只监听 loopback。
- 界面与文档为中文；报告正文可选中文或英文，界面本身不做多语言。
- 0.17.0 未发布到 PyPI；0.17.1 加入行业定期报告、可编辑富文档、用户模板与企业背景知识库；0.18.0 起以 `briefloop` 发布到 PyPI。

若本机已有旧服务运行，先结束其模型任务，再停止服务并执行新版本的 `./start.sh`。关闭浏览器不等于停止服务；更新源码也不会热替换正在运行的前后端。
