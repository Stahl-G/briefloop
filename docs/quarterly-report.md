# 行业季报模式

季报回答的不是“本季发生了哪些事”，而是“本季谁从什么状态变成了什么状态，方向和速度如何”。一周不看新闻的读者，也应能读完这份报告后重新建立对行业格局的判断：哪家领先、哪家掉队、哪条路线起势、哪个国家或区域的位置变了。

## 选择方式

- 文档类型选“商业报告”，用途选“行业季报（趋势与格局变化）”，即 `workflow_id=business_report`、`workflow_variant=industry_quarterly`。
- 聊天中提出“行业季报”或“季度格局变化”时，主 Agent 按同一用途提交。
- 只要覆盖窗口达到 80 天，或标题含“季报”“季度”“quarterly”“Q1–Q4”，也会按季度设定默认值。用户显式填写的预算、Scout 数和篇幅保持不变。

## 程序设定的边界

| 项目 | 周报 | 月报 | 季报 |
|---|---|---|---|
| 搜索 / 候选网址 / 页面 | 30 / 150 / 60 | 80 / 400 / 150 | 200 / 1,000 / 400 |
| Scout 上限 | 工作区设置 | 8 | 12 |
| 中文正文目标 / 上限 | 5,000 / 5,500 | 9,000 / 10,000 | 8,000 / 10,000 |

季报的正文不比月报长，篇幅留给判断，不留给罗列。

## 研究方法（模型决定）

1. **全景扫描**：第一轮先用少量宽口径搜索，查本季的行业综述、榜单和季度回顾，列出候选主体。不只靠记忆，因为记忆会漏掉新进入者，也可能带入旧事。
2. **选择主体**：按“本季是否改变了格局、读者是否需要据此判断”选 8–15 个主体，入选和未入选的理由都写进研究计划。次要主体可合并成一组。
3. **期初基线**：优先读上一期季报或期初月报；没有的话，派 Scout 查入选主体在期初的状态。
4. **期内变化与补查**：按维度 × 月份或主体组分派 Scout，再针对空缺做定向补查。

## 状态变化表（程序校验）

`prepare-report-data` 新增 `state_changes`，与原有的指标 `records` 同用一个工具和同一条来源校验：

- 每条记录包括主体、维度、变化类型，以及期初和期末两端的状态、日期和来源。变化类型有：新出现、反转、加速、停滞、事故、获得溢价、失去溢价、确认未变。
- 除“新出现”外，每条都必须有期初状态及其来源。
- 期初日期要在本期前三分之一以内，期末日期要在冻结的覆盖窗口之内。
- 不满足条件的记录会列为数据缺口，并在表中标为“未核验”。表格由工具生成，正文判断应与表格对应。

## 写作与审阅

- 结构依次为：本季结论（3–5 条主线变化）→ 格局变化（按主体或国家）→ 分维度分析 → 下季拐点与观察指标。
- Evaluator 和 Reviewer 另收一张季报核查卡：重点检查“从 X 到 Y”两端的证据和阶段表述，以及“未查到”被写成“无变化”的情况。缺少期初证据却写成趋势或反转的，按重大问题报告。

## 尚未支持

- 直写模式的写作者没有数据工具，季报的状态变化表需要走标准模式（Analyst）。
- 多期月报的状态变化表还不能自动汇总成季报，目前只能通过“开始下一期”读取上一期报告。
