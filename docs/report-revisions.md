# 报告反馈与修订

在报告右侧聊天提出反馈时，BriefLoop 先保存编辑稿，再将选中的版本与这条消息关联。
普通聊天与“开始下一期”沿用各自上下文，不会自动修改刚浏览过的报告。

## 补资料

已允许联网的报告，可在联网消息中继续补查。宿主根据真实用户消息开启修订研究阶段，沿用报告剩余预算。
初稿的研究轮次与已用额度保持原样；费用、来源和请求归入本次修订阶段。
阶段随消息完成、停止或中断结束，过期请求的返回结果不能进入下一次修订。
额度不足时保留已有稿件和材料，显示具体缺口。

## 改稿后的依据

每次修订保存新版本。仅调整颜色或格式时保留已有依据；正文改变后，只继承能定位到原样保留段落的数字、日期和逐句引用。
原稿仍保留完整历史。新版中失效的逐句绑定移除，来源、原文摘录与定位继续可查。

报告聊天完成一次实质改稿后，默认直写路径自动安排新版依据补全和评价，关闭该检查的自动改稿，避免循环重写。
补全使用新版实际引用的来源快照，包括本次新取的原文；正文保持不变。
检查结果区域显示“正在补全”或“待重新检查”。失败时保留新版，可通过既有检查任务恢复。

手动编辑只更新稿件和依据状态，不因每次保存启动模型。
来源定位、事实判断和用户采用仍分别记录；低分或待检查的工作稿可继续编辑、下载。

## 后续使用

作者按读者需要检查重要遗漏和篇幅分配，保留关键数字、比较对象及适用条件，研究操作记录放在工作区。
已核实的反馈通过既有 WikiSkill 方法验证进入学习；“下期沿用”保存用户认可的写作约定。
下一期沿用方法与约定，重新研究当期事实。
