# 先交初稿与继续检查

## 快速模式：已有材料直接写作

新增 `completion_mode=fast`，在新建报告的“完成方式”中选择“快速模式 · 已有材料直接出稿”。它与旧 `draft_first` 的“研究照常、手动续检”不同：直接将完整文本材料交给一次写作会话，没有主控分工、Scout、写前研究轮次，也不要求模型填写稿件 JSON。写作、检索规划和依据补全都是“纯文本回合”，按执行引擎分两档（`src/briefloop/plain_isolation.py`）：

- **无工具配置**：内置引擎注册零个工具，Pi 用其关闭全部工具的模式；仍记录宿主报告的工具活动，不以配置代替正文依据核查。
- **只读限制**：Codex、OpenCode 使用宿主只读权限，仍可能读取所选材料之外的信息；记录实际工具活动，不宣称全部工具关闭或材料隔离。
- **观察**：Antigravity、CodeBuddy 等桥接 CLI 的自带工具无法由 BriefLoop 关闭。快速模式仍可运行，但会话放在工作区之外的空目录，宿主报告的每次工具调用都会记入任务的“研究过程”和稿件研究记录（`fast_isolation`）；这只是记录，不宣称隔离。

各档的依据补全都会记录模型指出、且能在正文中逐字定位的无依据结论（`fast_unsupported`）。这不是穷尽检查，不能保证材料外信息都会被识别。正式交付仍需独立审阅，审阅者的隔离要求不变。

适用于已读取的文本材料，不设置额外的输入字符数门槛；没有材料、读取失败、独立风格参考或尚待拉取的连接器材料会在启动前提示选择完整流程。不会悄悄截断原文。当前路径不联网补搜、不维护企业背景，不支持在同一快速任务开启联网事实核查。界面明确说明这些取舍；原工作区设置不变。

正文返回后立即保存为可编辑、可下载的版本，再自动入队后台任务：先针对已保存正文补引用原文和重要数字绑定，再独立评价。程序从冻结原文定位逐字摘录，不将定位成功描述为语义支持。错误摘录保留拒收记录，缺失依据仍交评价。此路径不自动修订正文；用户可依据评价主动修改。

快速依据补全要求每条引用包含正文逐字原句，保存“结论 → 摘录 → 来源定位”。上下文由程序从冻结原文补入，包含来源标题、相邻行、章节标题及可识别的表格表头；重复摘录无法唯一定位时保留拒收，不默认绑定第一次出现的位置。旧引用无需补齐新字段才能读取。

数字检查显示已提交绑定的可核对数量与比例、未检查原因及正文数值候选；这不是全文正确率，裸数字或仅在表头声明单位的单元格也不因此宣称核对完成。英文明确单位支持 `USD thousands`、`US$ million` 等写法；未知量级不退化成裸币种数值。

快速稿后台评价增加“事实状态、时间与适用范围”和“依据语义支持”两项记录。未返回的检查显示未核对；摘录存在不自动转成语义通过。它们仍由同一后台评价执行，不增加写作前置步骤，不替代独立审阅。

依据补全创建正文不变的后继版本。若用户已经保存了自己的修改，后台只保留原版依据记录和评价，不覆盖用户稿件；未保存的编辑沿用现有编辑器保护。后台任务可停止、恢复；恢复保留原模型、要求、材料和初稿，不重新跑已完成的写作。失败仍可下载初稿。正式交付的独立审阅规则不变。

目标用时仍为软目标。材料原文完整交给所选模型；实际模型或服务的上下文限制仍然存在，若提供方拒绝请求，保留失败和材料，不伪造完成或静默删减。材料较多可能需要更久，不能承诺特定模型或复杂材料总能在几十秒内交稿。

## 快速联网：先选原文，再直接写作

`completion_mode=fast_web` 是独立选项，可从零上传材料开始。模型先提出少量公开查询，再从实际搜索候选中选择网页；程序通过现有受控搜索和来源读取接口执行。写作会话只读取得的正文，不暴露搜索或稿件装配工具；其后的保存、依据补全、普通评价和人工稿保护与材料快速模式相同。

第一版整次报告最多 3 次搜索、15 个候选网址、6 个原文网址；用户已有更小预算时取更小值。每批最多 3 个请求并行，不开展多轮 Scout 研究。时间仍为软目标，预算与时间不混为一谈。网页快照逐字保留，已选且读取成功的原文全部纳入，不因合计字符数排除网页或截断原文。

使用本任务冻结的 Tavily、DuckDuckGo、博查或智谱配置；仅选择宿主自带搜索时会提示改选受控渠道，不静默扩大权限。查询规划不包含上传文件正文。搜索摘要仅供挑选候选，不能成为报告依据；候选之外的模型编造 URL 不接纳。没有取得任何可读原文时保留失败任务，而不生成只有搜索摘要的报告。

本地 DNS/TLS/连接失败时，若 Tavily 本来就在已配置且获准的渠道中，可以批量提取选中的公开网页。此路径不放宽本地网页读取的地址保护，不用于私网、登录页或权限拒绝；保留直接读取失败，并标明新来源是提供方提取文本，不是网站 HTML/PDF 原始字节。同 URL 仍算一个原文额度；后备 API 请求独立留下回执，可能使用提供方额度。

查询、选择、搜索及原文读取分别保存回执。恢复复用已经完成的动作；外部请求已开始但本地回执不完整时保留“结果不确定”缺口，不自动重发或返还额度。联网并不等于事实核查：第一次输出仍是工作稿，普通评价不替代正式交付所需的独立审阅。

下文记录旧 `draft_first` 的行为，旧任务仍可继续。

报告需求中的 `completion_mode` 默认为 `standard`，保留原来的写作、检查及自动修订流程。选择 `draft_first` 才启用“先交初稿”；旧任务的 `research_tier=quick` 不会因此改变行为。研究深度、预算、篇幅与完成方式分别选择，不把“短报告”或“单轮研究”当作核验已经完成。

先交初稿未明确填写时间时，目标为约 10 分钟；明确填写的目标优先。这是软目标，超过目标仍继续正常写作，不中断作者、不删减必要内容。原有显式硬截止设置仍按用户配置执行。

初稿持续保存到现有版本体系，普通工作稿可编辑、下载 Word、HTML/PDF。写作阶段不自动派发 checkpoint Reviewer，结束时保留结构、引用、数字和版式的确定性检查记录，把独立评价、事实核查与自动修订显示为尚未开始。确定性检查不代表事实已经正确。

点击“继续完整检查”先保存当前编辑，再创建现有的 `assess` job，复用标准流程的写后检查；原设置启用自动修订时，必要时执行一次修订。检查绑定选中的稿件、来源、要求和原生成任务的模型、推理强度、角色模型、联网及审阅配置，不继承后来改过的设置。重复点击复用同一任务；失败或停止后用普通恢复入口继续。同一初稿链最多占用一次自动修订，用户新稿始终优先，原稿与失败结果保留。

如果原任务开启联网事实核查，本次子任务抓取的新材料可进入后续审阅。来源接纳事务保存 `admitted_sources`，只说明“该请求实际保存了哪些材料”，没有真实性、审阅或通过含义。续检查库核对所属父任务、版本及阶段，仅允许匹配的接纳回执扩展检查输入；原稿、要求、旧来源不能变化，无关并发上传不能混入。扩展后的绑定持久保存，恢复不会把它重新解释成另一批材料。

联网阶段失败不会被后来的一份完整评分掩盖。显式恢复保留原预算并复用未结束的核查任务；取消后恢复保留取消历史，不重新授予额度。预算耗尽、已结束阶段不自动重开。评价明确标为 incomplete 时，只有用户再次恢复才继续原评价会话；已接纳的 incomplete Review 保持不可变，以新的只读审阅结果继续检查。相同恢复次数重放不增加模型回合。

检查完成仅表示原配置所要求的检查阶段结束，不保证每个事实都获得支持。正式交付仍经过既有审阅与证据门槛。状态面板显示保存记录，日常刷新不重新读取全部来源原件；实际入队、执行和正式交付仍校验对应材料。

# 0.26.0 回归入口

`probes/fast_report_smoke.py` 使用一份明确虚构的材料，通过真实 `/api/generate` 启用 `completion_mode=fast`，完成写稿、补依据与普通评价。它不是把通用评价夹具改一个源码路径：保存冻结代码哈希、实际排队参数、首稿/后台耗时及完整公开检查记录（包括未检查项），不按 findings 数量自动打质量分。

只有明确同意发送合成材料并使用已配置模型额度后运行，例如：

```sh
PYTHONPATH=src python probes/fast_report_smoke.py --out /path/to/new-output \
  --model provider/model --effort high --allow-model-requests
```

该入口不会调用 Jev、联网搜索或读取个人报告。`tests/test_fast_qualifier_checks.py` 另验证 fast 和 fast_web 的冻结核查范围、缺失检查与矛盾回执；这些离线检查只证明程序行为。实际语义质量仍须回读保存的稿件与来源，L1/L2 题库的历史分数不能直接算为本版本验收。
