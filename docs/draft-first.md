# 先交初稿与继续检查

## 快速模式：已有材料直接写作

新增 `completion_mode=fast`，在新建报告的“完成方式”中选择“快速模式 · 已有材料直接出稿”。它与旧 `draft_first` 的“研究照常、手动续检”不同：直接将完整文本材料交给一次写作会话，没有主控分工、Scout、写前研究轮次，也不要求模型填写稿件 JSON。内置引擎在此会话注册零个工具；兼容 CLI 使用原有宿主的只读执行方式，不能据此宣称完全隔离宿主环境。

目前适用于已读取的文本材料，合计最多 10 万字符；没有材料、读取失败、超过上限、独立风格参考或尚待拉取的连接器材料会在启动前提示选择完整流程。不会悄悄截断原文。当前路径不联网补搜、不维护企业背景，不支持在同一快速任务开启联网事实核查。界面明确说明这些取舍；原工作区设置不变。

正文返回后立即保存为可编辑、可下载的版本，再自动入队后台任务：先针对已保存正文补引用原文和重要数字绑定，再独立评价。程序从冻结原文定位逐字摘录，不将定位成功描述为语义支持。错误摘录保留拒收记录，缺失依据仍交评价。此路径不自动修订正文；用户可依据评价主动修改。

依据补全创建正文不变的后继版本。若用户已经保存了自己的修改，后台只保留原版依据记录和评价，不覆盖用户稿件；未保存的编辑沿用现有编辑器保护。后台任务可停止、恢复；恢复保留原模型、要求、材料和初稿，不重新跑已完成的写作。失败仍可下载初稿。正式交付的独立审阅规则不变。

目标用时仍为软目标。字符上限是第一版的材料适用范围，不是各模型上下文上限的声明；不能承诺特定模型或复杂材料总能在几十秒内交稿。

下文记录旧 `draft_first` 的行为，旧任务仍可继续。

报告需求中的 `completion_mode` 默认为 `standard`，保留原来的写作、检查及自动修订流程。选择 `draft_first` 才启用“先交初稿”；旧任务的 `research_tier=quick` 不会因此改变行为。研究深度、预算、篇幅与完成方式分别选择，不把“短报告”或“单轮研究”当作核验已经完成。

先交初稿未明确填写时间时，目标为约 10 分钟；明确填写的目标优先。这是软目标，超过目标仍继续正常写作，不中断作者、不删减必要内容。原有显式硬截止设置仍按用户配置执行。

初稿持续保存到现有版本体系，普通工作稿可编辑、下载 Word、HTML/PDF。写作阶段不自动派发 checkpoint Reviewer，结束时保留结构、引用、数字和版式的确定性检查记录，把独立评价、事实核查与自动修订显示为尚未开始。确定性检查不代表事实已经正确。

点击“继续完整检查”先保存当前编辑，再创建现有的 `assess` job，复用标准流程的写后检查；原设置启用自动修订时，必要时执行一次修订。检查绑定选中的稿件、来源、要求和原生成任务的模型、推理强度、角色模型、联网及审阅配置，不继承后来改过的设置。重复点击复用同一任务；失败或停止后用普通恢复入口继续。同一初稿链最多占用一次自动修订，用户新稿始终优先，原稿与失败结果保留。

如果原任务开启联网事实核查，本次子任务抓取的新材料可进入后续审阅。来源接纳事务保存 `admitted_sources`，只说明“该请求实际保存了哪些材料”，没有真实性、审阅或通过含义。续检查库核对所属父任务、版本及阶段，仅允许匹配的接纳回执扩展检查输入；原稿、要求、旧来源不能变化，无关并发上传不能混入。扩展后的绑定持久保存，恢复不会把它重新解释成另一批材料。

联网阶段失败不会被后来的一份完整评分掩盖。显式恢复保留原预算并复用未结束的核查任务；取消后恢复保留取消历史，不重新授予额度。预算耗尽、已结束阶段不自动重开。评价明确标为 incomplete 时，只有用户再次恢复才继续原评价会话；已接纳的 incomplete Review 保持不可变，以新的只读审阅结果继续检查。相同恢复次数重放不增加模型回合。

检查完成仅表示原配置所要求的检查阶段结束，不保证每个事实都获得支持。正式交付仍经过既有审阅与证据门槛。状态面板显示保存记录，日常刷新不重新读取全部来源原件；实际入队、执行和正式交付仍校验对应材料。

## 本轮验证与未完成部分

离线行为检查使用真实 Store、Worker、InteractiveRuntime 状态机制及受控返回，覆盖可下载初稿、后台排队幂等、原配置冻结、材料变化、核查来源扩展、中断恢复、人工稿保护及旧模式的一次自动修订。Native 编译后引擎另验证了快速写作零工具、无 JSON 修复或提交轮次。

2026-09-28 经授权以虚构季度材料完成三个 OpenCode Go / DeepSeek v4.1 Flash High 实测：Native 两次首次保存为 18.8 和 19.3 秒，含后台检查分别约 203 和 120 秒；OpenCode CLI 企业报告首次保存 19.0 秒、含后台约 120 秒。后台均未改写正文、未自动创建 Reviewer。逐稿回读虚构来源，核对数字、环比/同比、毛利/净利润、百分点/百分比及管理层目标状态；并用实际页面下载 Word、核对工件封装，未做 WPS/桌面显示验收。这是小型功能验收，提示词和报告时间设置有调整，不是同条件性能排名，不能推广为一般速度或质量结论。OpenCode 子任务/中间回合用量可能缺失，无实际账单不报告美元成本。
