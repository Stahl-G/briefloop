# Jev 依据预检（可选）

在稿件右侧「检查与评价」展开「Jev 依据预检」。先查看所选稿件中将发送的结论、来源标题、摘录及上下文，再点击开始。快速稿需先完成后台补依据；旧稿如果只有来源链接、没有对应的正文原句，会明确显示未进入预检的引用数量。

Jev 使用独立的 TypeSafe API Key，与写作模型、OpenCode Go 或其他宿主额度无关。可在面板中保存本机密钥，或给服务配置 `TYPESAFE_API_KEY`；环境变量优先。保存密钥不调用服务。密钥不放入工作区、请求材料、任务记录或浏览器响应，实际调用由后台 HTTP 客户端发起，不向 Agent 开放主机文件工具。

## 行为与结果

- 默认不自动执行。用户确认后，只发送页面列出的结论及其完整所选上下文，不发送整份报告、其他工作区、原始运行日志或思考内容。
- 同一句依赖多个来源时一起预检。有来源不能定位，不悄悄丢弃后再判断支持；该句保持尚未核查。正文中尚无绑定的其他结论不在覆盖范围内。
- 返回「候选：证据支持」「候选：证据矛盾」「候选：证据不足」「候选：无法判断」，请求没有有效结果则显示「尚未核查」。摘录不含某事实不等于事实错误。
- 记录实际模型、公开概率分布、服务返回的输入/输出 token 和请求耗时。概率未经本任务校准，不是真实性概率；缺少 usage 时保持未知，无账单不推算费用。
- 结果按稿件版本和发送材料指纹保存。来源或协议变化后，旧观察明确标为过期。新稿不继承旧稿的结果。
- 相同请求重复提交会返回既有任务；手动恢复不会重发成功请求。遇到中断、超时或未取得有效回执的请求，保留未知，不静默重复扣费；这些条目需人工核查。取消后保留已收到结果。
- Jev 不改正文、评分、独立审阅状态、交付条件或 Wiki 学习许可。普通工作稿照常可编辑下载，正式交付仍需既有独立审阅。

产品接入采用 [TypeSafe 官方 API](https://docs.typesafe.ai/api) 的 Choice 协议，固定请求 `https://api.typesafe.ai/v1/systemone`、模型 `jev-latest`，同时保存服务实际返回模型。别名不代表固定权重，不据此宣称跨日期对照完全一致。

## 验证范围

相关自动检查使用合成材料验证授权、上下文、版本绑定、重复请求、失败保留与公开字段投影，不代表真实语义准确率或服务已连通。真实 Jev 调用需单独记录；未验证时不把本机配置成功写成模型验收。

`experiments/jev_semantic/` 保留开发/留出、概率和对照研究工具，输出仍是研究观察。它不替代本面板的产品任务，也不能用其分数自动放行报告。
